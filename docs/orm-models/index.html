ORM & Models

Раздел описывает, как в AirCMS создаются модели, как указываются типы данных, как работает чтение/запись/удаление, как происходит преобразование данных и какие conventions применяются автоматически.

Что такое модель в AirCMS

Модель — это PHP-класс, который наследуется от Air\Model\ModelAbstract и описывает структуру записи через PHPDoc. В AirCMS модель одновременно является описанием схемы, точкой доступа к базе данных и источником metadata для форм, CRUD-админки и API.

В отличие от классического Active Record, поля модели обычно не объявляются как реальные PHP-свойства. AirCMS читает их из аннотаций @property, а доступ к значениям выполняет через magic methods и document driver.

Описание структуры

Через @collection, @primary и @property модель сообщает ядру имя коллекции, primary-поле и список полей.

Работа с данными

Методы one(), all(), insert(), update(), save(), remove() делегируются database driver-у.

Автоматическое приведение типов

При записи и чтении AirCMS приводит значения к типам из @property: scalar, model reference, typed object или массив.

Conventions

Поля enabled, position, createdAt, updatedAt, url имеют специальное поведение.

Как создаётся модель

Минимальная модель должна наследоваться от ModelAbstract, иметь @collection и хотя бы одно @property. Если @primary не указан, primary-полем считается id.

app/Model/Article.php
<?php

declare(strict_types=1);

namespace App\Model;

use Air\Model\ModelAbstract;

/**
 * @collection Article
 *
 * @property string $id
 * @property string $title
 * @property string $url
 * @property string $description
 * @property boolean $enabled
 * @property integer $position
 * @property integer $createdAt
 * @property integer $updatedAt
 */
class Article extends ModelAbstract
{
}
Важно: имя коллекции в @collection используется driver-ом как имя MongoDB collection или MySQL table. В MongoDB поле модели id автоматически преобразуется в _id при запросах к базе.

Какие могут быть типы данных

Тип указывается во второй части @property. На его основании AirCMS понимает, как хранить значение и что вернуть при чтении свойства.

Ссылки на другие модели

Если тип поля является классом, который наследуется от ModelAbstract, AirCMS считает поле model reference. При записи можно передать модель или primary value. В базе будет храниться primary value, а при чтении AirCMS загрузит связанную модель.

app/Model/Category.php
<?php

namespace App\Model;

use Air\Model\ModelAbstract;

/**
 * @collection Category
 *
 * @property string $id
 * @property string $title
 * @property boolean $enabled
 */
class Category extends ModelAbstract
{
}
app/Model/Article.php
<?php

namespace App\Model;

use Air\Model\ModelAbstract;

/**
 * @collection Article
 *
 * @property string $id
 * @property string $title
 * @property Category $category
 * @property Category[] $relatedCategories
 */
class Article extends ModelAbstract
{
}
Запись и чтение связанной модели
$category = Category::one(['url' => 'news']);

$article = new Article();
$article->title = 'Новая статья';
$article->category = $category;
$article->relatedCategories = [$category];
$article->save();

// При чтении вернётся объект Category.
$article = Article::one($article->id);
$title = $article->category->title;

Typed Objects

Typed object — это вложенная структура на базе Air\Type\TypeAbstract. Она полезна, когда поле не является отдельной коллекцией, но имеет внутреннюю структуру: файл, SEO meta, блоки контента, настройки, координаты, контакты.

app/Type/Seo.php
<?php

namespace App\Type;

use Air\Type\TypeAbstract;

class Seo extends TypeAbstract
{
  public ?string $title = null;
  public ?string $description = null;
  public ?string $keywords = null;
}
Typed object внутри модели
<?php

namespace App\Model;

use Air\Model\ModelAbstract;
use App\Type\Seo;

/**
 * @collection Article
 *
 * @property string $id
 * @property string $title
 * @property Seo $seo
 */
class Article extends ModelAbstract
{
}
Использование typed object
$article = new Article();
$article->title = 'About us';
$article->seo = new Seo([
  'title' => 'About us',
  'description' => 'Company page',
]);
$article->save();

$article = Article::one($article->id);
$pageTitle = $article->seo->title;

Как работает преобразование данных

При записи свойства AirCMS смотрит metadata поля и приводит значение к формату хранения. При чтении делает обратное преобразование.

  1. Модель парсит PHPDoc и создаёт Meta.
  2. При $model->field = $value вызов попадает в DocumentAbstract::__set().
  3. Document driver вызывает castDataType().
  4. Scalar-типы приводятся через settype().
  5. Model reference сохраняется как primary value.
  6. Typed object сохраняется как raw array или JSON, в зависимости от driver-а.
  7. При чтении свойства AirCMS возвращает уже приведённое значение: scalar, модель, массив моделей или typed object.
Примеры автоматического преобразования
$article = new Article();
$article->views = '100';       // станет integer 100
$article->enabled = '1';       // станет boolean true
$article->category = $category; // сохранится как primary value
$article->seo = ['title' => 'SEO title']; // вернётся как объект Seo
$article->save();
