Генератор форм

Генератор форм в AirCMS нужен для быстрого создания admin-формы на основе meta-описания модели. Он читает поля модели, их имена, типы и enum-значения, после чего собирает готовую форму с правильными элементами.

Что это такое

Air\Form\Generator — это вспомогательный класс для админки. Он не заменяет обычные формы, а помогает быстро собрать типовую форму редактирования модели: title, url, description, image, enabled, meta, references, enum-поля и другие часто используемые поля.

Генератор форм лучше рассматривать как инструмент для CRUD-админки. В API обычно удобнее использовать чистый класс формы, потому что API-форма валидирует данные, но не обязана рисовать HTML-элементы.

Уровни генерации

В ядре есть три основных уровня генерации. Они отличаются тем, какие группы полей будут включены в форму.

МетодЧто генерируетКогда использовать
Generator::minimal()Базовые поля по именам: title, url, description, image, enabled, meta, richContent и т.д.Когда нужна простая CRUD-форма без автоматического добавления связей и enum-полей.
Generator::full()Базовые поля + model references + enum-поля.Когда модель типовая и можно доверить генератору большую часть формы.
Generator::fullRequired()Похоже на full(), но reference-поля создаются как обязательные.Когда связанные модели должны быть выбраны обязательно.
Базовое использование
use Air\Form\Generator;

$form = Generator::minimal($article);
$form = Generator::full($article);
$form = Generator::fullRequired($article);

Сигнатуры методов

Каждый метод принимает модель и дополнительный список элементов, которыми можно расширить или переопределить автоматически сгенерированные поля.

Air\Form\Generator
public static function minimal(?ModelAbstract $model = null, array $elements = []): Form
public static function full(?ModelAbstract $model = null, array $elements = []): Form
public static function fullRequired(?ModelAbstract $model, array $elements = []): Form

На основе чего генерируется форма

Генератор смотрит на $model->getMeta(). Meta строится из PHPDoc модели: @collection, @primary, @property, типа поля и enum-констант.

Модель, из которой можно сгенерировать форму
<?php

namespace App\Model;

use Air\Crud\Model\Language;
use Air\Model\ModelAbstract;
use Air\Type\File;
use Air\Type\Meta;
use Air\Type\RichContent;

/**
 * @collection Article
 *
 * @property string $id
 * @property string $title
 * @property string $url
 * @property string $description
 * @property File $image
 * @property File[] $images
 * @property RichContent[] $richContent
 * @property Meta $meta
 * @property Category $category
 * @property Category[] $tags
 * @property string $status
 * @property Language $language
 * @property boolean $enabled
 * @property integer $position
 * @property integer $createdAt
 * @property integer $updatedAt
 */
class Article extends ModelAbstract
{
  public const string STATUS_DRAFT = 'draft';
  public const string STATUS_PUBLISHED = 'published';
}

Какие поля модели учитывает генератор

Генератор использует не только тип поля, но и его имя. Поэтому для типовых CRUD-разделов важно придерживаться стандартных имён.

Generator::minimal()

minimal() удобен для простых разделов. Он создаёт типовые поля по стандартным именам, но не добавляет автоматически все связи с другими моделями и enum-поля.

Минимальная форма
protected function getForm($model = null): ?Form
{
  return Generator::minimal($model);
}

Дополнительные элементы можно передать вторым аргументом. Если элемент имеет то же имя, что и автоматически найденное поле, он переопределит generated-элемент.

Переопределение отдельных элементов
protected function getForm($model = null): ?Form
{
  return Generator::minimal($model, [
    Input::textarea('description', allowNull: true),
    Input::storage('image', allowNull: true),
  ]);
}

Generator::full()

full() подходит для типовых CRUD-разделов, где нужно получить почти полную форму по модели: основные поля, references и enum-поля.

Полная форма
protected function getForm($model = null): ?Form
{
  return Generator::full($model);
}

Если модель содержит связь с другой моделью, генератор создаст поле выбора модели. Если поле содержит enum-константы, будет создан Select.

References и enum в модели
/**
 * @property Category $category
 * @property Category[] $tags
 * @property string $status
 */
class Article extends ModelAbstract
{
  public const string STATUS_DRAFT = 'draft';
  public const string STATUS_PUBLISHED = 'published';
}

Generator::fullRequired()

fullRequired() используется, когда reference-поля должны быть обязательными. Например, товар всегда должен иметь категорию, а статья всегда должна быть привязана к автору.

Полная форма с обязательными связями
protected function getForm($model = null): ?Form
{
  return Generator::fullRequired($model);
}
Используйте fullRequired() аккуратно. Если в проекте есть черновики, импорт или неполные записи, обязательные reference-поля могут мешать сохранению промежуточных данных.

Группы и расположение полей

Если передать элементы обычным массивом, они попадут в группу General. Если передать ассоциативный массив, ключи станут названиями вкладок/групп в форме.

Группировка полей
protected function getForm($model = null): ?Form
{
  return Generator::full($model, [
    'General' => [
      Input::text('title'),
      Input::text('url'),
    ],
    'Content' => [
      Input::tiny('content'),
      Input::richContent('richContent'),
    ],
    'SEO' => [
      Input::meta('meta'),
    ],
  ]);
}

Когда использовать чистую форму

Генератор хорош для быстрых CRUD-разделов. Чистая форма лучше, когда структура сложнее стандартной или когда форму нужно переиспользовать вне admin manage.

СитуацияЧто выбратьПочему
Простая модель: title, url, description, image, enabledGenerator::minimal()Быстро и достаточно.
Типовой CRUD с категориями, тегами и статусамиGenerator::full()Генератор сам добавит references и enum.
Все связи обязательныGenerator::fullRequired()Reference-поля будут обязательными.
Нужно сложное расположение полей, подсказки, свои validatorsЧистая формаКод будет явным и предсказуемым.
Форма используется в APIЧистая формаAPI валидирует данные, но не обязан рисовать HTML.
Кастомная admin-страница не через manageЧистая формаЛегче контролировать action, method, значения и обработку.
Чистая форма для админки
<?php

namespace App\Form\Admin;

use Air\Form\Form;
use Air\Form\Input;
use Air\Validator\StringLength;

class ArticleForm extends Form
{
  public function __construct($model = null)
  {
    parent::__construct(options: [
      'data' => $model,
    ], elements: [
      Input::text('title', validators: [
        StringLength::class => [
          'min' => 3,
          'max' => 255,
        ],
      ]),
      Input::text('url'),
      Input::textarea('description', allowNull: true),
      Input::storage('image', allowNull: true),
      Input::checkbox('enabled'),
    ]);
  }
}
Использование чистой формы в CRUD-контроллере
protected function getForm($model = null): ?Form
{
  return new \App\Form\Admin\ArticleForm($model);
}

Рабочие кейсы

Страница настроек

Для Single можно использовать Generator::full(), если модель содержит стандартные поля: title, description, image, meta, enabled.

Каталог товаров

Для Many удобно начать с Generator::full(), а затем переопределить image, description и category своими элементами.

SEO-страницы

Если модель содержит url, title, content и meta, генератор быстро соберёт базовую форму.

Сложный checkout/settings flow

Лучше использовать чистую форму, потому что там обычно нужны свои validators, вложенные объекты и нестандартная обработка.
