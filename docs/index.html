AirCMS Core V3

AirCMS Core V3 — это PHP-фреймворк для backend/API-проектов, административных панелей, server-rendered UI-страниц и CLI-воркеров, которые работают вокруг одного общего ядра приложения.

Что такое AirCMS

AirCMS строит приложение вокруг одного публичного входного файла www/index.php, общего проектного конфига config.php и набора модулей: admin, api, ui, cli. Это позволяет держать админку, API, публичный UI и фоновые воркеры в одном проекте, но разделять их по доменам, маршрутам и namespace-структуре.

Фреймворк ориентирован на проекты, где много сущностей, CRUD-разделов, API-методов, очередей, файлового хранилища и интеграций. Модели описываются PHP-классами и PHPDoc-аннотациями, а поверх них можно строить формы, админские таблицы, API-маппинг и автоматические выборки.

Важно: документация описывает именно ядро AirCMS. Starter-проект и реальные проекты используются как примеры того, как ядро подключается и применяется на практике.

Основные возможности

MVC-ядро

Front controller, request/response, router, controllers, actions, views, layouts, plugins и error controllers.

Модули по доменам

Один проект может иметь отдельные зоны: admin.*, api.*, публичный ui и консольный cli.

ORM-подобный слой

Модели с PHPDoc-метаданными, MongoDB-драйвером по умолчанию и дополнительным MySQL-драйвером.

Admin CRUD

Готовые CRUD-контроллеры, формы, таблицы, настройки, виджеты и стандартные admin-разделы.

Typed Objects

Вложенные структуры данных через Air\Type\TypeAbstract: файлы, meta, rich content и кастомные типы проекта.

Интеграции и утилиты

HTTP client, storage, cache, email/SMS/Telegram queues, Google Translate, DeepL, DeepSeek, payments и другие helper-классы.

Архитектура

AirCMS запускает все HTTP- и CLI-запросы через один front controller. Дальше фреймворк определяет активный модуль по домену или CLI-route, находит маршрут, собирает имя controller-класса, создаёт view, запускает plugins, вызывает action и возвращает результат в response.

ЭтапЧто происходит
1. Entry pointwww/index.php подключает Composer autoload и передаёт config.php в Air\Core\Front.
2. BootstrapFront::bootstrap() создаёт Request, Response, Router, применяет php.ini/startup-настройки и подключает require-файлы.
3. ModuleRouter выбирает module по домену: admin/api/ui или cli.
4. RouteRouter сопоставляет URI с route-таблицей, извлекает параметры и определяет context/controller/action.
5. ControllerFront находит controller-класс, создаёт его, inject-ит request/response/router/view и вызывает action.
6. ResponseArray/object возвращаются как JSON, string — как body, null может привести к auto-render view.

Установка и composer scripts

В проекте на AirCMS обычно подключается core-пакет и используется starter-структура. В starter-проекте уже есть composer script assets, который создаёт symlink на admin assets ядра.

composer.json
{
  "repositories": [
    {
      "type": "git",
      "url": "https://github.com/aircms/core-v3.git"
    }
  ],
  "require": {
    "aircms/core-v3": "dev-main",
    "ext-mongodb": "*",
    "ext-mbstring": "*",
    "ext-curl": "*",
    "ext-json": "*",
    "ext-dom": "*",
    "ext-intl": "*",
    "ext-openssl": "*"
  },
  "scripts": {
    "assets": [
      "ln -sfn ../../vendor/aircms/core-v3/assets www/assets/air"
    ]
  }
}
Установка зависимостей и assets
composer install
composer assets
Не нужно вручную создавать symlink, если в проекте есть composer script assets. Ручная команда нужна только если script отсутствует или ты настраиваешь проект без starter-болванки.

Config::defaults()

Config::defaults() собирает базовую конфигурацию приложения: namespace проекта, loader, database, storage, logs, startup-настройки и router-таблицу модулей. Параметр project одновременно задаёт namespace для переменных окружения.

config.php
<?php

use Air\Config;
use Air\Core\Route;
use Air\Crud\Nav\Nav;

return Config::defaults(
    project: 'AIR',
    timezone: 'Europe/Kyiv',
    reportErrors: true,
    logs: true,
    db: [],
    extensions: [],

    admin: fn() => Config::admin(
        domain: 'admin.*',
        title: 'AirCMS',
        nav: [
            Nav::item('Content', items: [
                Nav::item('Articles', controller: 'article'),
            ]),
        ],
    ),

    api: fn() => Config::api(
        domain: 'api.*',
        strictRoutes: true,
        strictInject: true,
        cacheEnabled: false,
        routes: [
            '/articles' => Route::r(context: 'blog', controller: 'articles'),
            '/article/:article' => Route::r(
                context: 'blog',
                controller: 'articles',
                action: 'details'
            ),
        ],
    ),

    ui: fn() => Config::ui(
        domain: '*',
        routes: [
            '/' => Route::r(controller: 'index'),
        ],
    ),

    cli: fn() => Config::cli()
);
ПараметрНазначение
projectPrefix/namespace для env-переменных. Например AIR → AIR_DB_HOST.
timezoneПередаётся в startup через date_default_timezone_set.
reportErrorsУправляет display_errors, error_reporting и exception output.
logsВключает/отключает внутренние логи AirCMS.
dbПозволяет переопределить driver, servers, db, user, pass.
extensionsДополнительные секции верхнего уровня, которые будут merged в итоговый config.

Config::admin(), api(), ui(), cli()

Модульные helper-методы возвращают готовую конфигурацию для конкретной зоны приложения. Router выбирает активную зону по домену или CLI-route.

МетодОсновные параметры
Config::admin()domain, title, settings, nav, reportErrors, richContent, require, login, password, tiny.
Config::api()domain, strictRoutes, strictInject, cacheEnabled, routes, require.
Config::ui()domain, strictInject, strictRoutes, cacheEnabled, routes, require.
Config::cli()strictInject, strictRoutes, routes, require.

Environment variables

AirCMS читает env-переменные через Config::getEnv(). Если в конфиге указано project: 'AIR', то все переменные должны начинаться с AIR_. Если поменять project на ATWA, prefix станет ATWA_.

.env для project: AIR
AIR_DB_HOST=localhost
AIR_DB_PORT=27017
AIR_DB_DB=aircms
AIR_DB_USER=
AIR_DB_PASS=

AIR_FS_URL=https://storage.example.com
AIR_FS_KEY=secret-storage-key

AIR_ADMIN_AUTH_ROOT_LOGIN=root
AIR_ADMIN_AUTH_ROOT_PASSWORD=change-me
AIR_ADMIN_TINY_KEY=
.env для project: ATWA
ATWA_DB_HOST=localhost
ATWA_DB_PORT=27017
ATWA_DB_DB=atwa
ATWA_FS_URL=https://storage.example.com
ATWA_FS_KEY=secret-storage-key
Не коммить секреты. Root-пароль админки, ключ storage, API tokens, payment keys и SMTP-пароли должны жить в окружении, а не в Git.

Web server: Apache и Nginx

DocumentRoot должен указывать на папку www. Все несуществующие static-файлы должны попадать в www/index.php.

Apache VirtualHost
<VirtualHost *:80>
    ServerName api.example.com
    DocumentRoot /var/www/project/www

    <Directory /var/www/project/www>
        Options FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/aircms-error.log
    CustomLog ${APACHE_LOG_DIR}/aircms-access.log combined
</VirtualHost>
www/.htaccess
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule ^ index.php [QSA,L]
Nginx + PHP-FPM
server {
    listen 80;
    server_name api.example.com;
    root /var/www/project/www;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }

    location ~ /\. {
        deny all;
    }
}

Основные концепции

Front

Air\Core\Front — центральная точка исполнения. Он создаёт loader, request, response, router, view, controller и запускает lifecycle.

Bootstrap

Если существует App\Bootstrap, Front создаёт его и передаёт config. Его используют для проектной инициализации.

Modules

Admin, Api, Ui, Cli — отдельные зоны приложения с разными routes, controllers и views.

Controllers / Actions

Controller — класс, action — public method. Если route не указывает action, используется index().

Views

Для UI AirCMS может auto-render-ить .phtml script и layout, если action вернул null.

Plugins

Plugins выполняются до и после action. Их можно располагать на уровне всех модулей, конкретного модуля или context.

Как понимать Routing

Route в AirCMS описывает не только URL, но и то, какой module/context/controller/action должен быть вызван.

Route без явного action
'/someRoute/:someParam' => Route::r(
    context: 'catalog',
    controller: 'property'
),

Такой route в соответствующем модуле будет искать:

Разрешение controller/action
App\Module\Api\Catalog\Controller\Property::index()

Правила:

Часть routeЧто означает
context: catalogПапка Catalog внутри активного модуля. Например app/Module/Api/Catalog.
controller: propertyФайл-класс Controller/Property.php. В AirCMS папка называется Controller, не Controllers.
action не указанИспользуется index().
controller не указанИспользуется Index.
:someParamЗначение из URL попадает в request/get params и может быть injected в action argument.
Route с явным action
'/article/:article' => Route::r(
    context: 'blog',
    controller: 'articles',
    action: 'details'
),

Этот route будет вести в:

App\Module\Api\Blog\Controller\Articles::details()
