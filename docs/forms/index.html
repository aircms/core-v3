Forms

Формы в AirCMS используются не только для отрисовки HTML-элементов в админке. Это общий механизм описания входных данных, фильтрации, валидации, получения очищенных значений и отображения ошибок.

Что такое форма в AirCMS

Air\Form\Form — это контейнер элементов. Каждый элемент описывает одно поле: имя, значение по умолчанию, label, description, hint, filters, validators, allowNull и способ отрисовки.

API usage

В API форма обычно используется как validator/schema для входящих данных. Элементы не нужно рисовать, важно только проверить request и получить очищенные значения.

Admin/UI usage

В админке и UI эта же форма может быть отрисована как HTML. Поэтому выбор элемента влияет не только на значение, но и на интерфейс.

Filters

Фильтры приводят значение к нужному виду: trim, lowercase, email, phone, strip tags, safe и т.д.

Validators

Валидаторы проверяют значение и добавляют сообщения об ошибках: email, phone, number, string length, regex, contain и custom callbacks.

Минимальный пример

Форму можно создать через Form::inputs() и передать массив элементов. После этого вызвать validateOfFail() или isValid().

Базовая форма
<?php

use Air\Form\Form;
use Air\Form\Input;

$form = Form::inputs(null, [
  Input::text('title'),
  Input::email('email'),
  Input::checkbox('enabled', allowNull: true),
]);

$data = $form->validateOfFail([
  'title' => 'Hello',
  'email' => 'john@example.com',
  'enabled' => true,
]);

return $data;

Как это работает под капотом

  1. Форма получает список элементов.
  2. При инициализации каждому элементу устанавливается значение из модели/массива, если оно есть.
  3. При валидации форма передаёт каждому элементу значение из входного массива по имени элемента.
  4. Элемент сначала проверяет validators.
  5. Если ошибок нет, элемент применяет filters.
  6. Форма возвращает значения через getValues() или выбрасывает Air\Form\Exception\Validation.
Важно: метод в текущем AirCMS называется validateOfFail(). Если в проекте ты привык говорить “validate or fail”, в коде всё равно нужно использовать именно существующее имя метода.

Собственный класс формы

Для реальных проектов удобно выносить форму в отдельный класс, например App\Form\Api\ContactForm. Такой класс можно использовать и в API для валидации, и в UI/Admin для отрисовки.

Минимальный класс формы
<?php

namespace App\Form\Api;

use Air\Form\Form;
use Air\Form\Input;

class ContactForm extends Form
{
  public function init($model = null, array $elements = []): void
  {
    parent::init($model, [
      Input::text('name'),
      Input::email('email'),
      Input::text('message'),
    ]);
  }
}
