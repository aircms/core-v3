Validation

Форма может валидировать весь набор входных данных, возвращать очищенные значения, хранить ошибки в элементах и выбрасывать исключение Air\Form\Exception\Validation.

Методы формы для валидации и данных

МетодСигнатураОписание
isValid()isValid(array $data = []): boolПроверяет форму и заполняет ошибки внутри элементов.
validateOfFail()validateOfFail(?array $data = []): arrayЕсли форма невалидна, выбрасывает Air\Form\Exception\Validation. Если валидна — возвращает getValues().
validated()static validated(?array $data = []): arrayСоздаёт форму текущего класса и валидирует данные.
getValues()getValues(): arrayВозвращает значения элементов после фильтров.
getCleanValues()getCleanValues(): arrayВозвращает clean values элементов. Для model/file/typed элементов может отличаться от getValues().
getErrorMessages()getErrorMessages(): arrayВозвращает ошибки по каждому элементу.
getErrorFields()getErrorFields(): arrayВозвращает список имён полей с ошибками.

Как создать свой класс формы

Если форма используется в нескольких местах, её лучше вынести в отдельный класс. Так правила валидации, фильтры и список полей не будут размазаны по контроллерам.

Обычно класс формы наследуется от Air\Form\Form и переопределяет метод init(). Внутри init() нужно вызвать parent::init() и передать массив элементов.

app/Form/Api/ContactForm.php
<?php

declare(strict_types=1);

namespace App\Form\Api;

use Air\Filter\StripTags;
use Air\Filter\Trim;
use Air\Form\Form;
use Air\Form\Input;
use Air\Validator\Email;
use Air\Validator\StringLength;

class ContactForm extends Form
{
  public function init($model = null, array $elements = []): void
  {
    parent::init($model, [
      Input::text('name', validators: [
        StringLength::class => [
          'min' => 2,
          'max' => 120,
          'message' => 'Имя должно быть от 2 до 120 символов',
        ],
      ]),
      Input::text('email', validators: [
        Email::class,
      ]),
      Input::text('message', filters: [
        Trim::class,
        StripTags::class,
      ], validators: [
        StringLength::class => [
          'min' => 10,
          'max' => 3000,
          'message' => 'Сообщение должно быть от 10 до 3000 символов',
        ],
      ]),
    ]);
  }
}
Важно: в API для длинного текста можно использовать Input::text('message'), потому что форма здесь не рисует интерфейс. В админке для того же поля обычно лучше использовать Input::textarea('message'), потому что элемент будет отрисован пользователю.
app/Form/Admin/ArticleForm.php
<?php

declare(strict_types=1);

namespace App\Form\Admin;

use Air\Form\Form;
use Air\Form\Input;
use Air\Validator\StringLength;

class ArticleForm extends Form
{
  public function init($model = null, array $elements = []): void
  {
    parent::init($model, [
      Input::text('title', validators: [
        StringLength::class => [
          'min' => 3,
          'max' => 160,
        ],
      ]),
      Input::textarea('description', allowNull: true),
      Input::checkbox('enabled', allowNull: true),
    ]);
  }
}

Когда в форму передаётся модель или массив данных, Form::init() проставляет начальные значения в элементы по их именам. Поэтому title, description и enabled автоматически получат значения из модели Article.

Как использовать класс формы для валидации данных в API

В API форма обычно не отрисовывается. Она работает как схема входных данных: принимает request params, валидирует их, применяет filters и возвращает очищенный массив.

API controller через ContactForm::validated()
<?php

declare(strict_types=1);

namespace App\Module\Api\Controller;

use Air\Core\Controller;
use Air\Form\Exception\Validation;
use App\Form\Api\ContactForm;

class Contact extends Controller
{
  public function send(): array
  {
    try {
      $data = ContactForm::validated($this->getParams());
    } catch (Validation $exception) {
      $this->getResponse()->setStatusCode(400);

      return [
        'success' => false,
        'errors' => $exception->getForm()->getErrorMessages(),
      ];
    }

    return [
      'success' => true,
      'data' => $data,
    ];
  }
}

Статический метод ContactForm::validated() создаёт экземпляр формы и вызывает validateOfFail(). Если данные невалидны, будет выброшено Air\Form\Exception\Validation.

API controller через isValid()
<?php

$form = new ContactForm();

if (!$form->isValid($this->getParams())) {
  $this->getResponse()->setStatusCode(400);

  return [
    'success' => false,
    'errors' => $form->getErrorMessages(),
  ];
}

$data = $form->getValues();

return [
  'success' => true,
  'data' => $data,
];

Вариант через isValid() удобен, когда нужно не выбрасывать исключение, а явно управлять ответом в текущем action.

Добавление вычисленного или служебного параметра перед валидацией
<?php

$data = [
  ...$this->getParams(),
  'source' => $this->getParam('source') ?? 'website',
];

$validated = ContactForm::validated($data);

Такой подход полезен, когда часть данных приходит из request, а часть добавляется сервером: например source, userId, ip или createdAt.

Как переиспользовать класс формы в UI/Admin

Один и тот же подход можно использовать и в UI/Admin. Разница в том, что в админке форма часто ещё и отрисовывается, поэтому тип элемента влияет на внешний вид.

Использование ArticleForm в controller
<?php

namespace App\Module\Admin\Controller;

use Air\Core\Controller;
use App\Form\Admin\ArticleForm;
use App\Model\Article;

class ArticleEdit extends Controller
{
  public function index(?Article $article = null): void
  {
    $article = $article ?? new Article();
    $form = new ArticleForm(['data' => $article]);

    if ($this->getRequest()->isPost() && $form->isValid($this->getParams())) {
      $article->populate($form->getValues());
      $article->save();

      $this->redirect('/article');
      return;
    }

    $this->getView()->assign('form', $form);
  }
}

Если форма невалидна, элементы сохраняют сообщения об ошибках и старые значения. После этого можно снова вывести <?php echo $form; ?> во view script.

Валидация в API

В API форму обычно создают внутри action, передают туда $this->getParams() или JSON body и возвращают данные/ошибки как массив.

API controller
<?php

namespace App\Module\Api\Controller;

use Air\Core\Controller;
use Air\Form\Exception\Validation;
use Air\Form\Form;
use Air\Form\Input;
use Air\Validator\StringLength;

class Contact extends Controller
{
  public function send(): array
  {
    $form = Form::inputs(null, [
      Input::text('name', validators: [
        StringLength::class => [
          'min' => 2,
          'max' => 120,
          'message' => 'Имя должно быть от 2 до 120 символов',
        ],
      ]),
      Input::email('email'),
      Input::text('message'),
    ]);

    try {
      $data = $form->validateOfFail($this->getParams());
    } catch (Validation $exception) {
      $this->getResponse()->setStatusCode(400);

      return [
        'success' => false,
        'errors' => $exception->getForm()->getErrorMessages(),
      ];
    }

    return [
      'success' => true,
      'data' => $data,
    ];
  }
}

Валидация в UI/Admin

В UI/Admin форма не только валидирует данные, но и может быть отрисована. Если форма невалидна, элементы сохраняют ошибки и старые значения, поэтому форму можно снова вывести пользователю.

UI/Admin controller
<?php

namespace App\Module\Admin\Controller;

use Air\Core\Controller;
use Air\Form\Form;
use Air\Form\Input;
use App\Model\Article;

class ArticleEdit extends Controller
{
  public function index(?Article $article = null): void
  {
    $article = $article ?? new Article();

    $form = Form::inputs($article, [
      Input::text('title'),
      Input::textarea('description', allowNull: true),
      Input::checkbox('enabled', allowNull: true),
    ]);

    if ($this->getRequest()->isPost()) {
      if ($form->isValid($this->getParams())) {
        $article->populate($form->getValues());
        $article->save();

        $this->redirect('/article');
        return;
      }
    }

    $this->getView()->assign('form', $form);
  }
}

Как устанавливать и читать ошибки

Ошибки хранятся на уровне элементов. Их можно читать через форму или напрямую у элемента. Также можно вручную установить ошибки элементу.

Errors
<?php

$form->isValid($data);

$allErrors = $form->getErrorMessages();
$errorFields = $form->getErrorFields();
$titleErrors = $form->getElement('title')->getErrorMessages();

$form->getElement('title')->setErrorMessages([
  'Такой заголовок уже используется',
]);

Как получать данные из формы

Values
<?php

if ($form->isValid($this->getParams())) {
  $values = $form->getValues();
  $cleanValues = $form->getCleanValues();

  $title = $form->getElement('title')->getValue();
  $categoryId = $form->getElement('category')->getCleanValue();
}

Рекомендуемый шаблон своего класса формы

Рекомендуется наследоваться от Air\Form\Form и передавать элементы в parent::__construct(elements: [...]).

app/Form/Api/MyForm.php
<?php

namespace App\Form\Api;

use Air\Form\Form;
use Air\Form\Input;

class MyForm extends Form
{
  public function __construct()
  {
    parent::__construct(elements: [
      Input::text('name'),
      Input::email('email'),
      Input::textarea('message', allowNull: true),
    ]);
  }
}
