Views and layouts

View layer в AirCMS отвечает за HTML-рендеринг: подключает нужный script, передаёт данные из контроллера в шаблон, оборачивает результат в layout и предоставляет helpers/shorts для генерации повторяемой разметки.

Что это такое

View в AirCMS — это объект Air\View\View, который создаётся ядром для каждого запроса и передаётся в controller. Через него action может передать данные в шаблон, выбрать другой script, отключить layout, отрендерить partial или собрать HTML вне стандартного auto-render flow.

В обычном MVC-сценарии controller отвечает за бизнес-логику, model — за данные, а view — за представление. В AirCMS view layer особенно полезен в ui-модуле и в admin/CRUD-интерфейсах, где action должен вернуть HTML-страницу, а не JSON-ответ.

Важно: если action возвращает массив, AirCMS сериализует его в JSON. Если action возвращает строку — эта строка становится body ответа. Если action возвращает null, AirCMS пытается автоматически отрендерить view script и, если включён layout, оборачивает script в layout.

Как это работает под капотом

Во время выполнения запроса Air\Core\Front определяет активный module/context/controller/action через router, создаёт объект Air\View\View и передаёт его в controller через setView().

  1. FrontHelper::getView() собирает путь к папке view.
  2. Если папка View существует, она становится базовым path для view.
  3. Если найден Layouts/index.phtml, layout включается автоматически.
  4. Script определяется по паре controller/action.
  5. Если action вернул null, вызывается $view->render().
  6. Если layout включён, результат script помещается в $this->getContent() и вызывается $view->renderLayout().
Request URI
    ↓
Router
    ↓
Controller action
    ↓
View script: View/Scripts/{controller}/{action}.phtml
    ↓
Layout: View/Layouts/index.phtml
    ↓
Response body

Структура

Для UI-модуля view-файлы обычно находятся внутри app/Module/Ui/View. Если используется context, то view может лежать внутри context-папки: app/Module/Ui/Catalog/View.

Базовая структура UI-модуля
app/
└── Module/
    └── Ui/
        ├── Controller/
        │   └── Index.php
        └── View/
            ├── Layouts/
            │   └── index.phtml
            └── Scripts/
                └── index/
                    └── index.phtml
Структура с context
app/
└── Module/
    └── Ui/
        └── Catalog/
            ├── Controller/
            │   └── Property.php
            └── View/
                ├── Layouts/
                │   └── index.phtml
                └── Scripts/
                    └── property/
                        ├── index.phtml
                        └── details.phtml
Правило поиска script: если route ведёт в controller: property и action: details, AirCMS будет искать файл View/Scripts/property/details.phtml внутри активного module/context.

Layout

Layout — это общий HTML-каркас страницы. В него обычно помещают <!doctype html>, <html>, <head>, подключение assets, header, footer и общий контейнер страницы.

По умолчанию AirCMS ищет layout здесь:

View/Layouts/index.phtml

Содержимое конкретного script попадает внутрь layout через метод $this->getContent().

app/Module/Ui/View/Layouts/index.phtml
<!doctype html>
<html lang="ru">
<head>
    <?php echo $this->head(
        favicon: '/assets/favicon.svg',
        assets: [
            '/assets/css/app.css',
            '/assets/js/app.js',
        ]
    ); ?>
    <title><?php echo $this->title ?? 'AirCMS'; ?></title>
</head>
<body>
    <header class="site-header">
        <a href="<?php echo $this->uri(['controller' => 'index']); ?>">Главная</a>
    </header>

    <main class="site-main">
        <?php echo $this->getContent(); ?>
    </main>

    <footer class="site-footer">
        AirCMS - <a href="https://aircms.pro">aircms.pro</a>
    </footer>
</body>
</html>

Как отключить layout

Layout можно отключить, если нужно вернуть только fragment HTML, XML, plain text или другой нестандартный response.

<?php

namespace App\Module\Ui\Controller;

use Air\Core\Controller;

class Fragment extends Controller
{
    public function menu(): ?string
    {
        $this->getView()->setLayoutEnabled(false);

        return null;
    }
}

Script

Script — это конкретный .phtml-файл, который соответствует controller/action. Он содержит HTML конкретной страницы или её части.

Controller
<?php

namespace App\Module\Ui\Controller;

use Air\Core\Controller;
use App\Model\Article;

class Articles extends Controller
{
    public function details(Article $article): ?string
    {
        $this->getView()->article = $article;
        $this->getView()->title = $article->title;

        return null;
    }
}
app/Module/Ui/View/Scripts/articles/details.phtml
<article class="article-page">
    <h1><?php echo $this->article->title; ?></h1>

    <div class="article-description">
        <?php echo $this->article->description; ?>
    </div>
</article>

Как выбрать другой script вручную

Иногда action один, но шаблон нужно выбрать динамически. Для этого используется setScript().

<?php

namespace App\Module\Ui\Controller;

use Air\Core\Controller;

class Landing extends Controller
{
    public function index(string $type = 'default'): ?string
    {
        if ($type === 'promo') {
            $this->getView()->setScript('landing/promo');
        }

        return null;
    }
}

Работа в controller/action

Внутри controller доступ к view получается через $this->getView(). Данные можно передавать через magic properties, assign() или setVars().

<?php

namespace App\Module\Ui\Controller;

use Air\Core\Controller;
use App\Model\Article;

class Blog extends Controller
{
    public function index(): ?string
    {
        $articles = Article::all(['enabled' => true], ['createdAt' => -1]);

        $this->getView()->articles = $articles;
        $this->getView()->assign('title', 'Блог');
        $this->getView()->setVars([
            'description' => 'Последние публикации проекта',
            'currentPage' => 1,
        ]);

        return null;
    }
}
View/Scripts/blog/index.phtml
<section class="blog-page">
    <h1><?php echo $this->title; ?></h1>
    <p><?php echo $this->description; ?></p>

    <?php foreach ($this->articles as $article): ?>
        <article class="blog-card">
            <h2><?php echo $article->title; ?></h2>
            <a href="<?php echo $this->uri(['controller' => 'blog', 'action' => 'details'], ['article' => $article->url]); ?>">
                Читать дальше
            </a>
        </article>
    <?php endforeach; ?>
</section>

Методы View

Ниже перечислены основные методы Air\View\View, которые полезны при разработке UI-страниц, partials и нестандартного HTML-рендеринга.

Метод Что делает Когда использовать
assign($key, $value)Передаёт одну переменную в view.Когда нужно явно добавить значение в шаблон.
setVars($vars)Передаёт сразу массив переменных.Когда данные уже собраны в массив.
getVars()Возвращает все переменные view.Для отладки или передачи набора данных дальше.
setPath($path)Меняет базовую папку View.Для рендера шаблонов из другого модуля или core/admin views.
render($template = null, $vars = [])Рендерит script из View/Scripts.Для ручного рендера script или partial.
renderLayout()Рендерит текущий layout.Обычно вызывается ядром автоматически.
setLayoutEnabled(false)Отключает layout.Для fragments, XML, plain HTML, AJAX-ответов.
setLayoutTemplate($template)Выбирает layout.Когда нужно использовать другой layout, например print.
setScript($script)Выбирает script вручную.Когда action должен рендерить не стандартный controller/action.
setAutoRender(false)Отключает автоматический render script.Когда action сам формирует response.
setContent($content)Устанавливает готовый HTML content и отключает auto render.Для ручного layout/render flow.
getContent()Возвращает текущий content.Внутри layout.
setMeta($meta)Устанавливает объект meta tags.Для SEO-страниц.
getMeta()Возвращает meta или default meta.В layout/helper head().
View::tpl($template, $vars)Рендерит .phtml рядом с файлом, который вызвал метод.Для шаблонов вне MVC.
Передача переменных
$this->getView()->assign('title', 'Каталог');
$this->getView()->setVars([
    'items' => $items,
    'filters' => $filters,
]);

return null;
Выбор layout и script
$this->getView()->setLayoutTemplate('print');
$this->getView()->setScript('invoice/print');

return null;

Работа вне MVC

Иногда HTML нужно собрать не из controller/action, а внутри service, mail template renderer, CLI worker или другого PHP-файла. Для этого можно создать View вручную или использовать View::tpl().

Ручной render через Air\View\View
<?php

use Air\View\View;

$view = new View();
$view->setPath(__DIR__ . '/../Module/Ui/View');
$view->setVars([
    'title' => 'Письмо',
    'userName' => 'Edward',
]);

$html = $view->render('email/welcome');
View::tpl()
<?php

use Air\View\View;

$html = View::tpl('card', [
    'title' => 'AirCMS',
    'description' => 'Лёгкий PHP framework',
]);
card.phtml рядом с вызывающим PHP-файлом
<div class="card">
    <h3><?php echo $this->title; ?></h3>
    <p><?php echo $this->description; ?></p>
</div>
Ограничение: при ручном создании View вне MVC некоторые helpers могут зависеть от Front::getInstance(), router или config. Например, uri(), asset() и head() ожидают, что приложение уже инициализировано.

View helpers

Helpers вызываются как методы view: $this->asset(), $this->uri(), $this->partial(). Под капотом View::__call() ищет helper сначала в проекте, а затем в core namespace Air\View\Helper.

Helper Что делает Где полезен
asset()Генерирует <script>, <link rel="stylesheet"> или asset URL с учётом prefix.Подключение CSS/JS/images/fonts.
base()Возвращает HTML <base href="...">.В layout, когда нужно задать базовый URL для относительных ссылок.
head()Собирает meta charset, viewport, base, meta object, favicon, fonts, codes и assets.Основной helper для <head>.
partial()Рендерит другой script с переменными.Переиспользуемые блоки: карточки, меню, формы.
partialCached()Рендерит partial через single-request cache.Повторяющиеся блоки внутри одного запроса.
uri()Собирает URL через router assemble.Генерация ссылок внутри layout и script.
asset()
<?php echo $this->asset('/assets/css/app.css'); ?>
<?php echo $this->asset('/assets/js/app.js'); ?>
<?php echo $this->asset(['/assets/css/app.css', '/assets/js/app.js']); ?>
head()
<?php echo $this->head(
    favicon: '/assets/favicon.svg',
    assets: [
        '/assets/css/app.css',
        '/assets/js/app.js',
    ]
); ?>
uri()
<a href="<?php echo $this->uri(
    ['controller' => 'articles', 'action' => 'details'],
    ['article' => $article->url]
); ?>">
    <?php echo $article->title; ?>
</a>
partial()
<?php echo $this->partial('partials/card', [
    'title' => $article->title,
    'url' => $article->url,
]); ?>

Свой helper в проекте

Если helper не найден в проекте, AirCMS использует core helper. Поэтому проект может переопределить или расширить helpers.

app/Module/Ui/View/Helper/Price.php
<?php

namespace App\Module\Ui\View\Helper;

use Air\View\Helper\HelperAbstract;

class Price extends HelperAbstract
{
    public function call(float $value, string $currency = 'EUR'): string
    {
        return number_format($value, 2, '.', ' ') . ' ' . $currency;
    }
}
Использование helper
<strong><?php echo $this->price(1250.5); ?></strong>

Shorts

Shorts — это набор глобальных функций для быстрой генерации HTML. Они лежат в Air\View\Shorts и подключаются ядром. В отличие от helpers, shorts не привязаны к объекту View и вызываются напрямую: div(), a(), img(), text(), table().

Идея shorts: писать меньше HTML вручную и собирать безопасную повторяемую разметку через PHP-функции, особенно в admin/CRUD templates и небольших UI-blocks.

Renderer shorts

ShortЧто делаетПример
content()Приводит строку, число, bool, массив, Generator или Closure к HTML-строке.content(['A', 'B'], ', ')
src()Возвращает URL из строки или Air\Type\File.src($file)
when()Возвращает content только если условие истинно.when($user, 'Hello')
 
<?php echo when($article->enabled, div(
    class: 'badge bg-success',
    content: 'Published'
)); ?>

HTML tag shorts

Функция tag() — базовая. Остальные функции являются удобными обёртками.

tag()
<?php echo tag(
    tagName: 'section',
    class: ['hero', 'hero-primary'],
    attr: ['id' => 'intro'],
    data: ['section' => 'home'],
    content: [
        h1('AirCMS'),
        p(''),
    ]
); ?>
div(), h2(), p(), a()
<?php echo div(
    class: 'card',
    content: [
        h2($article->title),
        p($article->description),
        a('/article/' . $article->url, 'Читать дальше', 'btn btn-primary'),
    ]
); ?>
img() с Air\Type\File или строкой
<?php echo img(
    src: $article->image,
    class: 'article-image',
    alt: $article->title,
    width: 800,
    height: 450
); ?>

ShortЧто делаетГде полезен
form()Создаёт <form>.Простые frontend-формы.
hidden()Создаёт hidden input.CSRF, id, служебные параметры.
text()Создаёт text input.Поиск, имя, title.
textarea()Создаёт textarea.Описание, комментарий, сообщение.
email()Создаёт email input.Контактные формы.
tel()Создаёт tel input.Телефон.

Простая форма через shorts
<?php echo form(
    method: 'post',
    action: '/contact',
    class: 'contact-form',
    content: [
        text('name', class: 'form-control', placeholder: 'Ваше имя'),
        email('email', class: 'form-control', placeholder: 'Email'),
        textarea('message', class: 'form-control', placeholder: 'Сообщение'),
        checkbox('agree', '1', false, ['id' => 'agree']),
        button('Отправить', class: 'btn btn-primary', isSubmit: true),
    ]
); ?>

Table shorts

table(), thead(), tbody(), tr(), th(), td()
<?php echo table(
    class: 'table',
    content: [
        thead(tr([
            th('ID'),
            th('Title'),
            th('Enabled'),
        ])),
        tbody(array_map(
            fn($article) => tr([
                td($article->id),
                td($article->title),
                td($article->enabled ? 'Yes' : 'No'),
            ]),
            $articles
        )),
    ]
); ?>

Icon shorts

faIcon() и gsIcon()
<?php echo faIcon('house'); ?>
<?php echo faIcon('github', data: ['provider' => 'github']); ?>

Rich content short

richContent() помогает отрендерить массив Air\Type\RichContent с кастомными renderer callbacks для разных типов блоков.

<?php echo richContent(
    content: $article->richContent,
    textRenderer: fn($value) => p($value, 'rich-text'),
    htmlRenderer: fn($value) => div($value, 'rich-html'),
    fileRenderer: fn($value) => img($value, 'rich-image'),
    containerClassName: 'rich-content',
    itemClassName: 'rich-content-item'
); ?>

Рекомендуемые паттерны

Держите controller тонким

Controller должен выбрать данные, передать их во view и выбрать script/layout. Сложную подготовку данных лучше выносить в service или model methods.

Не смешивайте API и UI

Если endpoint должен вернуть JSON — возвращайте массив. Если страница должна вернуть HTML — используйте null и view script.

Partial для повторяемых блоков

Карточки, меню, хлебные крошки и виджеты лучше выносить в partial, чтобы не дублировать HTML.

Shorts для компактной разметки

Shorts удобны для небольших UI-фрагментов, таблиц и форм, но большие страницы часто читаются лучше в обычном HTML/PHTML.
