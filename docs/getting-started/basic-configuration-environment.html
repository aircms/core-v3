Basic configuration & Environment variables

В AirCMS конфигурация проекта описывается обычным PHP-файлом, чаще всего config.php. Этот файл возвращает массив настроек, по которому Air\Core\Front понимает, какой модуль запустить, какой домен обработать, какие routes использовать, как подключиться к базе данных и какие сервисы включить.

Что это такое

Basic configuration — это центральная точка настройки AirCMS-проекта. В ней описываются общие настройки ядра, база данных, storage, логирование, timezone, а также отдельные модули: admin, api, ui и cli.

Конфигурация обычно лежит в корне проекта:

project/
    app/
    config.php
    composer.json
    www/
        index.php

Публичная точка входа www/index.php подключает Composer autoload, загружает config.php и передаёт результат в Air\Core\Front.

<?php

require_once __DIR__ . '/../vendor/autoload.php';

$config = require_once __DIR__ . '/../config.php';

echo \Air\\Core\\Front::getInstance($config)
    ->bootstrap()
    ->run();
Главная идея: AirCMS не требует отдельного конфигурационного языка. Конфиг — это PHP-код, поэтому в нём можно использовать классы, функции, условия, env-переменные, project-specific helpers и любые массивы.

Basic configuration: полный пример

Ниже пример конфигурации, где одновременно подключены все основные модули AirCMS: Admin, Api, Ui и Cli. Это не минимальный пример, а расширенный шаблон, который показывает основные параметры.

config.php
<?php

declare(strict_types=1);

use Air\Config;
use Air\Core\Route;
use Air\\Crud\\Nav\\Nav;
use Air\Type\FaIcon;

return Config::defaults(
    project: 'AIR',
    timezone: 'Europe/Bucharest',
    reportErrors: true,
    logs: true,

    db: [
        'driver' => 'mongodb',
        'servers' => [[
            'host' => Config::getEnv('DB_HOST', 'localhost'),
            'port' => (int) Config::getEnv('DB_PORT', 27017),
        ]],
        'db' => Config::getEnv('DB_DB', 'aircms'),
        'user' => Config::getEnv('DB_USER'),
        'pass' => Config::getEnv('DB_PASS'),
    ],

    admin: fn() => Config::admin(
        domain: 'admin.*',
        title: 'AirCMS Admin',
        settings: [
            [
                Nav::SETTINGS_SYSTEM,
                Nav::SETTINGS_STORAGE,
                Nav::SETTINGS_LOGS,
            ],
            [
                Nav::SETTINGS_LANGUAGES,
                Nav::SETTINGS_PHRASES,
            ],
            [
                Nav::SETTINGS_EMAIL_SETTINGS,
                Nav::SETTINGS_EMAIL_TEMPLATES,
                Nav::SETTINGS_EMAIL_QUEUE,
            ],
        ],
        nav: [
            Nav::item('Content', FaIcon::ICON_FILE_LINES, items: [
                Nav::item('Articles', controller: 'articles'),
                Nav::item('Pages', controller: 'pages'),
            ]),
        ],
        reportErrors: true,
        require: [
            __DIR__ . '/app/Helper/admin.php',
        ],
        login: 'root',
        password: 'change-me',
        tiny: null,
    ),

    api: fn() => Config::api(
        domain: 'api.*',
        strictRoutes: true,
        strictInject: true,
        cacheEnabled: false,
        routes: [
            '/articles' => Route::r(
                context: 'blog',
                controller: 'articles'
            ),
            '/article/:article' => Route::r(
                context: 'blog',
                controller: 'articles',
                action: 'details'
            ),
        ],
        require: [
            __DIR__ . '/app/Helper/api.php',
        ],
    ),

    ui: fn() => Config::ui(
        domain: '*',
        strictInject: true,
        strictRoutes: true,
        cacheEnabled: true,
        routes: [
            '/' => Route::r(controller: 'index'),
            '/page/:page' => Route::r(controller: 'pages', action: 'details'),
        ],
        require: [
            __DIR__ . '/app/Helper/ui.php',
        ],
    ),

    cli: fn() => Config::cli(
        strictInject: false,
        strictRoutes: false,
        routes: [
            'email/consume' => Route::r(controller: 'email', action: 'consume'),
            'telegram/consume' => Route::r(controller: 'telegram', action: 'consume'),
        ],
        require: [
            __DIR__ . '/app/Helper/cli.php',
        ],
    ),

    extensions: [
        'project' => [
            'name' => 'AirCMS Project',
            'version' => '1.0.0',
        ],
    ],
);

В реальном проекте не обязательно указывать все параметры. Если оставить параметр пустым, AirCMS использует значение по умолчанию. Например, Config::api() по умолчанию использует domain: 'api.*', strictRoutes: true и strictInject: true.

Основные настройки Config::defaults()

Config::defaults() собирает общий конфиг приложения. Именно здесь задаётся project namespace, timezone, база данных, storage, логирование и список доступных модулей.

КлючЗначение по умолчаниюОписание
adminnullClosure, которая возвращает конфигурацию admin-модуля. Если не передана, домен admin не будет добавлен в router.
apinullClosure, которая возвращает конфигурацию API-модуля. Обычно содержит домен api.* и список routes.
uinullClosure, которая возвращает конфигурацию UI-модуля. Обычно используется для публичных HTML-страниц.
clinullClosure, которая возвращает конфигурацию CLI-модуля. В router добавляется под ключом cli.
projectAIRNamespace/prefix для переменных окружения. Например project: 'AIR' означает AIR_DB_HOST, AIR_FS_KEY, AIR_ADMIN_AUTH_ROOT_LOGIN.
extensions[]Дополнительные root-level настройки. Они добавляются в итоговый config через spread. Используйте для проектных секций, которые нужны вашему приложению.
timezoneEurope/KyivПередаётся в startup как date_default_timezone_set. Для Румынии обычно можно указать Europe/Bucharest.
reportErrorstrueВключает/выключает отображение ошибок и режим exception reporting на базовом уровне. На production обычно ставят false.
logstrueВключает встроенный логгер AirCMS через air.logs.enabled.
db[]Переопределяет настройки базы данных. Значения из этого массива применяются поверх env-настроек, которые AirCMS собирает по умолчанию.

Что создаёт Config::defaults()

Внутри итогового массива AirCMS формирует секцию air и секцию router. Секция air содержит системные настройки ядра, а router содержит domain-based routing между модулями.

[
    'air' => [
        'modules' => '\\App\\Module',
        'exception' => true,
        'loader' => [
            'namespace' => 'App',
            'path' => '/path/to/project/app',
            'groupedController' => true,
        ],
        'db' => [
            'driver' => 'mongodb',
            'servers' => [[
                'host' => 'localhost',
                'port' => 27017,
            ]],
            'db' => 'aircms',
        ],
        'storage' => [
            'url' => null,
            'key' => null,
        ],
        'logs' => [
            'enabled' => true,
            'exception' => true,
        ],
    ],
    'router' => [
        'admin.*' => [...],
        'api.*' => [...],
        '*' => [...],
        'cli' => [...],
    ],
]

Настройки модуля Admin Config::admin()

Admin-модуль отвечает за административную панель, CRUD-разделы, встроенные widgets/settings, авторизацию, assets админки и UI-helpers.

КлючЗначение по умолчаниюОписание
domainadmin.*Маска домена, по которой router выберет admin-модуль. Например admin.example.com.
titleAirCmsНазвание админ-панели. Попадает в air.admin.title.
settingsnullСписок встроенных settings-разделов. Если null, используется Nav::getAllSettings().
nav[]Основное меню админки. Обычно собирается через Air\Crud\Nav\Nav::item().
reportErrorstrueУправляет ошибками именно для admin-модуля: air.exception, display_errors, error_reporting.
richContentnullСписок типов RichContent. Если null, используется RichContent::getAllTypes().
require[]Файлы, которые нужно подключить при старте admin-модуля. Core автоматически добавляет shortcuts и UI helpers админки.
loginnullFallback-логин root-админа. Может быть переопределён переменной {{PROJECT}}_ADMIN_AUTH_ROOT_LOGIN.
passwordnullFallback-пароль root-админа. Может быть переопределён переменной {{PROJECT}}_ADMIN_AUTH_ROOT_PASSWORD.
tinynullFallback TinyMCE key. Может быть переопределён переменной {{PROJECT}}_ADMIN_TINY_KEY.

Пример минимального admin-конфига

admin: fn() => Config::admin(
    domain: 'admin.*',
    title: 'AirCMS Admin',
    nav: [
        Nav::item('Content', items: [
            Nav::item('Articles', controller: 'articles'),
        ]),
    ],
)
Важно: root login/password лучше хранить в переменных окружения, а не прямо в config.php. Аргументы login и password удобно использовать только как fallback для локальной разработки.

Настройки модуля Api Config::api()

API-модуль обычно возвращает JSON-ответы и используется для backend endpoints. В нём чаще всего описываются strict routes, action injection и domain api.*.

КлючЗначение по умолчаниюОписание
domainapi.*Маска домена API-модуля. Например api.example.com.
strictRoutestrueЕсли включено, запрос должен совпасть с явно описанным route. Если выключено, router может использовать fallback-логику.
strictInjecttrueЕсли включено, injection параметров action работает строже и отсутствие обязательных параметров приводит к ошибке.
cacheEnabledfalseВключает persistent cache через air.cache.enabled для API-модуля.
routes[]Список маршрутов API. Ключ — URL pattern, значение — Route::r(...) или callable.
require[]Дополнительные PHP-файлы, которые нужно подключить для API-модуля.
api: fn() => Config::api(
    domain: 'api.*',
    strictRoutes: true,
    strictInject: true,
    routes: [
        '/articles' => Route::r(context: 'blog', controller: 'articles'),
        '/article/:article' => Route::r(
            context: 'blog',
            controller: 'articles',
            action: 'details'
        ),
    ],
)

Настройки модуля UI Config::ui()

UI-модуль используется для server-rendered страниц: layouts, view scripts, HTML-страницы, публичный сайт или документационный сайт.

КлючЗначение по умолчаниюОписание
domain*Маска домена публичного UI. Обычно *, если UI должен принимать основной домен проекта.
strictInjecttrueСтрогий режим injection для UI controllers.
strictRoutestrueСтрогий режим route matching для UI.
cacheEnabledfalseВключает persistent cache для UI-модуля.
routes[]Список публичных HTML routes. Например /, /page/:page.
require[]Дополнительные файлы для подключения в UI-модуле.
ui: fn() => Config::ui(
    domain: '*',
    routes: [
        '/' => Route::r(controller: 'index'),
        '/about' => Route::r(controller: 'pages', action: 'about'),
        '/page/:page' => Route::r(controller: 'pages', action: 'details'),
    ],
)

Настройки модуля Cli Config::cli()

CLI-модуль используется для console-команд, workers, очередей, парсеров, scheduled jobs и фоновой обработки.

КлючЗначение по умолчаниюОписание
strictInjectfalseПо умолчанию CLI injection менее строгий, потому что CLI-команды часто запускаются с разными наборами аргументов.
strictRoutesfalseПо умолчанию CLI routes не strict. CLI route обычно передаётся как route=name/action.
routes[]Список CLI routes. Если не нужен явный список, можно использовать стандартный route через query/argv.
require[]Дополнительные файлы для подключения в CLI-модуле.
cli: fn() => Config::cli(
    routes: [
        'email/consume' => Route::r(controller: 'email', action: 'consume'),
        'telegram/consume' => Route::r(controller: 'telegram', action: 'consume'),
    ],
)

CLI route обычно запускается через тот же entry point:

php www/index.php route=email/consume

Environment variables

AirCMS читает переменные окружения через Config::getEnv(). Метод не ищет переменную напрямую по имени DB_HOST, а добавляет к ней project namespace.

// project: 'AIR'
Config::getEnv('DB_HOST', 'localhost');
// ищет AIR_DB_HOST, если переменной нет — вернёт localhost

// project: 'ATWA'
Config::getEnv('DB_HOST', 'localhost');
// ищет ATWA_DB_HOST, если переменной нет — вернёт localhost

Это позволяет держать на одном сервере несколько AirCMS-проектов и не смешивать их настройки. Например, один проект может использовать AIR_DB_HOST, а другой — ATWA_DB_HOST.

Пример env-переменных для project: AIR
# Namespace проекта: project: 'AIR'
AIR_DB_HOST=localhost
AIR_DB_PORT=27017
AIR_DB_DB=aircms
AIR_DB_USER=
AIR_DB_PASS=

AIR_FS_URL=https://storage.example.com
AIR_FS_KEY=storage-secret-key

AIR_ADMIN_AUTH_ROOT_LOGIN=root
AIR_ADMIN_AUTH_ROOT_PASSWORD=change-me
AIR_ADMIN_TINY_KEY=your-tinymce-key
Важно: ядро AirCMS использует getenv(). Это значит, что переменные должны быть доступны PHP-процессу: через Apache SetEnv, PHP-FPM pool config, Docker environment, Supervisor environment, shell export или ваш собственный dotenv-loader.

Основные env-переменные AirCMS

ПеременнаяЗначение по умолчаниюОписание
{{PROJECT}}_DB_HOSTlocalhostХост MongoDB-сервера. Для project: 'AIR' это AIR_DB_HOST.
{{PROJECT}}_DB_PORT27017Порт MongoDB-сервера.
{{PROJECT}}_DB_DBnullНазвание базы данных. Обязательно укажите для реального проекта.
{{PROJECT}}_DB_USERnullПользователь базы данных.
{{PROJECT}}_DB_PASSnullПароль базы данных.
{{PROJECT}}_FS_URLnullURL файлового storage-сервиса. Используется Air\Storage.
{{PROJECT}}_FS_KEYnullКлюч доступа к storage-сервису.
{{PROJECT}}_ADMIN_AUTH_ROOT_LOGINзначение аргумента loginRoot login для входа в админку. Env имеет приоритет над аргументом login.
{{PROJECT}}_ADMIN_AUTH_ROOT_PASSWORDзначение аргумента passwordRoot password для входа в админку. Env имеет приоритет над аргументом password.
{{PROJECT}}_ADMIN_TINY_KEYзначение аргумента tinyTinyMCE key для редактора в админке. Env имеет приоритет над аргументом tiny.

Как переопределять значения

1. Через переменные окружения

Это основной способ для production. Значения не попадают в Git и могут отличаться на локальной машине, staging и production.

# Namespace проекта: project: 'AIR'
AIR_DB_HOST=localhost
AIR_DB_PORT=27017
AIR_DB_DB=aircms
AIR_DB_USER=
AIR_DB_PASS=

AIR_FS_URL=https://storage.example.com
AIR_FS_KEY=storage-secret-key

AIR_ADMIN_AUTH_ROOT_LOGIN=root
AIR_ADMIN_AUTH_ROOT_PASSWORD=change-me
AIR_ADMIN_TINY_KEY=your-tinymce-key

2. Через Apache

<VirtualHost *:80>
    ServerName api.example.com
    DocumentRoot /var/www/project/www

    SetEnv AIR_DB_HOST localhost
    SetEnv AIR_DB_PORT 27017
    SetEnv AIR_DB_DB aircms
    SetEnv AIR_ADMIN_AUTH_ROOT_LOGIN root
    SetEnv AIR_ADMIN_AUTH_ROOT_PASSWORD change-me

    <Directory /var/www/project/www>
        Require all granted
        AllowOverride All
    </Directory>
</VirtualHost>

3. Через PHP-FPM

; /etc/php/8.3/fpm/pool.d/www.conf

env[AIR_DB_HOST] = localhost
env[AIR_DB_PORT] = 27017
env[AIR_DB_DB] = aircms
env[AIR_ADMIN_AUTH_ROOT_LOGIN] = root
env[AIR_ADMIN_AUTH_ROOT_PASSWORD] = change-me

4. Через Supervisor для CLI workers

[program:aircms-email-worker]
directory=/var/www/project
command=php www/index.php route=email/consume
autostart=true
autorestart=true
environment=AIR_DB_HOST="localhost",AIR_DB_PORT="27017",AIR_DB_DB="aircms"

5. Через аргументы конфига

Для базы данных массив db в Config::defaults() применяется поверх env-настроек, поэтому он может переопределить {PROJECT}_DB_HOST, {PROJECT}_DB_PORT, {PROJECT}_DB_DB и другие DB-ключи.

return Config::defaults(
    project: 'AIR',

    // Этот массив будет применён поверх env-конфига базы данных.
    db: [
        'driver' => 'mongodb',
        'servers' => [[
            'host' => '10.0.0.2',
            'port' => 27017,
        ]],
        'db' => 'aircms_production',
    ],
);

6. Особенность admin credentials

Для admin credentials логика обратная: Config::admin() передаёт login, password и tiny как fallback в Config::getEnv(). Если env-переменная существует, она имеет приоритет.

return Config::defaults(
    project: 'AIR',

    admin: fn() => Config::admin(
        login: 'root-from-config',
        password: 'password-from-config',
    ),
);

// Если в окружении есть AIR_ADMIN_AUTH_ROOT_LOGIN и AIR_ADMIN_AUTH_ROOT_PASSWORD,
// AirCMS возьмёт значения из окружения, а не из аргументов login/password.

Namespace переменных окружения

Параметр project не просто название проекта. В рамках Config::getEnv() это prefix для всех env-переменных.

project: 'AIR'
AIR_DB_HOST=localhost
AIR_DB_PORT=27017
AIR_DB_DB=aircms
AIR_FS_KEY=air-storage-key
project: 'ATWA'
ATWA_DB_HOST=localhost
ATWA_DB_PORT=27017
ATWA_DB_DB=atwa
ATWA_FS_KEY=atwa-storage-key

Так можно запускать несколько проектов на одном сервере, не боясь, что один проект случайно прочитает credentials другого проекта.

Рекомендации

Для локальной разработки

Можно использовать fallback-значения в config.php, локальный MongoDB и reportErrors: true.

Для production

Пароли, storage keys, database credentials и API tokens храните только в окружении сервера. Для production обычно ставят reportErrors: false.

Для нескольких проектов

Используйте разные значения project: например AIR, DOMIK, ATWA. Это разделит env namespace.

Для CLI workers

Проверяйте, что env-переменные доступны именно CLI-процессу. Переменные Apache не всегда видны worker-процессам, запущенным через Supervisor.
