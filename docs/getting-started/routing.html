Routing

Routing в AirCMS — это слой, который связывает входящий URL с конкретным модулем, контекстом, контроллером, action-методом и параметрами запроса. На этой странице разобраны все основные варианты роутов и механизм automatic injection в action.

Что такое Routing в AirCMS

В AirCMS все HTTP- и CLI-запросы проходят через один entry point — www/index.php. После загрузки конфигурации Air\Core\Front передаёт запрос в Air\Core\Router. Router определяет:

Модуль

admin, api, ui или cli. Модуль обычно выбирается по домену, например api.* или admin.*.

Context

Дополнительная папка внутри модуля. Например context: 'catalog' означает папку Catalog.

Controller

Класс контроллера внутри папки Controller. Например controller: 'property' означает файл Property.php.

Action

Метод контроллера. Если action не указан явно, AirCMS вызывает index().

Важно: в структуре AirCMS папка называется Controller в единственном числе, а не Controllers.

Где описываются роуты

Роуты обычно описываются в config.php внутри конфигурации конкретного модуля: Config::api(), Config::ui() или Config::cli(). Для admin-модуля чаще используется CRUD navigation, но технически routing-механизм общий.

config.php
<?php

use Air\Config;
use Air\Core\Route;

return Config::defaults(
    project: 'AIR',

    api: fn() => Config::api(
        domain: 'api.*',
        strictRoutes: true,
        strictInject: true,
        routes: [
            '/' => Route::r(),

            '/catalog' => Route::r(
                context: 'catalog',
                controller: 'catalog'
            ),

            '/catalog/property/:property' => Route::r(
                context: 'catalog',
                controller: 'property',
                action: 'details'
            ),
        ]
    ),

    ui: fn() => Config::ui(
        domain: '*',
        routes: [
            '/' => Route::r(controller: 'index'),
        ]
    ),

    cli: fn() => Config::cli(
        routes: [
            '/notification/email' => Route::r(
                controller: 'notification',
                action: 'email'
            ),
        ]
    )
);

Ключ массива — это URI-шаблон. Значение — описание route. Обычно оно создаётся через Route::r().

Route::r()

Route::r() — helper для создания массива route-настроек. Он принимает context, controller, action и статические params.

Сигнатура
Route::r(
    ?string $context = null,
    ?string $controller = null,
    ?string $action = null,
    ?array $params = null
);
ПараметрЧто означаетЗначение по умолчанию
contextПапка-контекст внутри модуля. Например Catalog, Blog, Seo.Пусто, то есть контроллер ищется прямо в модуле.
controllerИмя контроллера. AirCMS делает ucfirst() и ищет класс в папке Controller.index
actionМетод контроллера.index
paramsСтатические параметры, которые будут добавлены в request и urlParams.null

Какие могут быть роуты

В AirCMS route может быть очень явным или почти пустым. Чем меньше параметров указано, тем больше используется значений по умолчанию: controller = index, action = index.

1. Route без context, controller и action

routes: [
    '/' => Route::r(),
]

Для API-модуля такой route будет искать:

App\Module\Api\Controller\Index::index()

Для UI-модуля тот же принцип:

App\Module\Ui\Controller\Index::index()

2. Route без context, но с controller

routes: [
    '/auth' => Route::r(controller: 'auth'),
]

AirCMS не видит action, поэтому вызывает index():

App\Module\Api\Controller\Auth::index()
app/Module/Api/Controller/Auth.php
<?php

namespace App\Module\Api\Controller;

use Air\Core\Controller;

class Auth extends Controller
{
    public function index(): array
    {
        return [
            'status' => 'auth endpoint',
        ];
    }
}

3. Route без context, но с controller и action

routes: [
    '/auth/login' => Route::r(
        controller: 'auth',
        action: 'login'
    ),
]

Такой route будет искать:

App\Module\Api\Controller\Auth::login()

4. Route с context, но без controller

routes: [
    '/candidates' => Route::r(context: 'candidate'),
]

Если controller не указан, используется index. Если action не указан, тоже используется index:

App\Module\Api\Candidate\Controller\Index::index()

Такой вариант удобен, когда context — это отдельная область API, а входная точка этой области называется Index.

5. Route с context и controller, но без action

routes: [
    '/catalog/property' => Route::r(
        context: 'catalog',
        controller: 'property'
    ),
]

Action не указан, значит будет вызван index():

App\Module\Api\Catalog\Controller\Property::index()
app/Module/Api/Catalog/Controller/Property.php
<?php

namespace App\Module\Api\Catalog\Controller;

use Air\Core\Controller;

class Property extends Controller
{
    public function index(): array
    {
        return [
            'items' => [],
        ];
    }
}

6. Route с context, controller и action

routes: [
    '/article/:article' => Route::r(
        context: 'blog',
        controller: 'articles',
        action: 'details'
    ),
]

Такой route будет искать:

App\Module\Api\Blog\Controller\Articles::details()

Часть :article — это URL-параметр. Для запроса /article/hello-world AirCMS добавит параметр article = hello-world в request.

7. Route со статическими params

routes: [
    '/articles' => Route::r(
        context: 'blog',
        controller: 'articles',
        params: [
            'type' => 'public',
        ]
    ),
]

Статические params добавляются в urlParams и request. Их можно получить через $this->getParam('type') или принять в action через injection.

public function index(string $type): array
{
    return [
        'type' => $type,
    ];
}

8. Wildcard route

Если ни один route не подошёл, Router может проверить специальный route *. Его значение должно быть callable. Такой route удобен для SEO, динамических страниц, CMS-страниц и собственных fallback-правил.

routes: [
    '*' => function (string $uri): ?array {
        if (str_starts_with($uri, '/page/')) {
            return Route::r(
                context: 'page',
                controller: 'page',
                action: 'details',
                params: [
                    'url' => trim($uri, '/'),
                ]
            );
        }

        return null;
    },
]
Важно: wildcard route сработает только после проверки обычных routes. Если strictRoutes включён и wildcard не вернул route, AirCMS выбросит ошибку роутинга.

strictRoutes и fallback-поведение

Поведение Router зависит от параметра strictRoutes в конфигурации модуля.

api: fn() => Config::api(
    domain: 'api.*',
    strictRoutes: true,
    routes: [
        '/articles' => Route::r(
            context: 'blog',
            controller: 'articles'
        ),
    ]
)
РежимЧто происходит
strictRoutes: trueЕсли URI не найден в routes и wildcard не помог, AirCMS выбрасывает ошибку RouterWasNotFound.
strictRoutes: falseAirCMS может использовать fallback: первая часть URI становится controller, вторая — action, следующие пары становятся параметрами.

Например при strictRoutes: false запрос /article/details/id/123 может быть разобран как:

controller = article
action     = details
id         = 123

Для публичного API чаще лучше использовать strictRoutes: true, чтобы API оставался предсказуемым и не принимал случайные URL.

URL-параметры

В URI-шаблоне параметры начинаются с двоеточия: :article, :property, :language. Router извлекает их из URL, записывает в urlParams и добавляет в request как GET-параметры.

routes: [
    '/:language/article/:article' => Route::r(
        context: 'blog',
        controller: 'articles',
        action: 'details'
    ),
]

Для запроса:

/en/article/hello-world

AirCMS получит:

language = en
article  = hello-world
Ограничение: path-параметры в текущем Router рассчитаны на значения из букв, цифр, - и _. Для сложных значений используйте query/body-параметры или собственную обработку.

Action injection

Action injection — это автоматическая передача параметров в метод контроллера. AirCMS смотрит на аргументы action-метода, берёт значения из route params, GET, POST или JSON body, приводит их к нужному типу и передаёт в метод.

Общая логика такая:

  1. Router находит route и извлекает URL-параметры.
  2. Request содержит данные из $_GET, $_POST, $_REQUEST или JSON body.
  3. Front::inject() смотрит на параметры action-метода.
  4. Для каждого параметра берётся значение по имени параметра.
  5. Если указан тип, значение приводится к этому типу или превращается в model/typed object.
public function details(string $article): array
{
    return [
        'article' => $article,
    ];
}

Если route содержит :article, параметр $article будет заполнен автоматически.

Injection скалярных типов

AirCMS умеет автоматически приводить значения к базовым PHP-типам: int, string, bool, array. Если параметр не найден, используется default value, если он указан в сигнатуре метода.

String из route parameter

routes: [
    '/article/:url' => Route::r(
        context: 'blog',
        controller: 'articles',
        action: 'details'
    ),
]
public function details(string $url): array
{
    return [
        'url' => $url,
    ];
}

Запрос /article/hello-world передаст в action строку hello-world.

Integer из route parameter

routes: [
    '/page/:page' => Route::r(
        context: 'blog',
        controller: 'articles'
    ),
]
public function index(int $page = 1): array
{
    return [
        'page' => $page,
    ];
}

Запрос /page/5 передаст 5 как integer.

Boolean из GET/POST

public function index(bool $enabled = true): array
{
    return [
        'enabled' => $enabled,
    ];
}

Запрос /articles?enabled=0 передаст значение в параметр $enabled. Важно помнить, что PHP-функция boolval() имеет свои правила приведения строк.

Необязательные параметры

public function index(
    int $page = 1,
    int $limit = 20,
    string $query = ''
): array {
    return [
        'page' => $page,
        'limit' => $limit,
        'query' => $query,
    ];
}

Если page, limit или query не пришли в запросе, будут использованы значения по умолчанию из сигнатуры метода.

Injection GET, POST и JSON body

Параметры могут приходить не только из URL-шаблона, но и из query string, формы, POST-запроса или JSON body.

Одиночные GET-параметры

GET /api/articles?page=2&limit=10&query=sea
public function index(
    int $page = 1,
    int $limit = 20,
    string $query = ''
): array {
    return [
        'page' => $page,
        'limit' => $limit,
        'query' => $query,
    ];
}

Массив из GET

GET /api/properties?ids[]=1&ids[]=2&ids[]=3
public function index(array $ids = []): array
{
    return [
        'ids' => $ids,
    ];
}

Вложенный массив из GET

GET /api/properties?filter[price][min]=100000&filter[price][max]=250000&filter[type]=apartment
public function index(array $filter = []): array
{
    return [
        'filter' => $filter,
        'minPrice' => $filter['price']['min'] ?? null,
        'maxPrice' => $filter['price']['max'] ?? null,
        'type' => $filter['type'] ?? null,
    ];
}

POST form-data или x-www-form-urlencoded

POST /api/contact
name=John&email=john@example.com&message=Hello
public function index(
    string $name,
    string $email,
    string $message
): array {
    return [
        'success' => true,
        'name' => $name,
        'email' => $email,
        'message' => $message,
    ];
}

JSON body

Если заголовок Content-Type содержит application/json, AirCMS читает тело запроса и кладёт JSON-данные в request params.

{
    "title": "New article",
    "enabled": true,
    "tags": ["php", "aircms"],
    "meta": {
        "title": "SEO title",
        "description": "SEO description"
    }
}
public function create(
    string $title,
    bool $enabled = false,
    array $tags = [],
    array $meta = []
): array {
    return [
        'title' => $title,
        'enabled' => $enabled,
        'tags' => $tags,
        'meta' => $meta,
    ];
}

Injection моделей

Если action-параметр типизирован классом модели, который наследуется от Air\Model\ModelAbstract, AirCMS может автоматически загрузить модель из базы данных.

Модель по id

routes: [
    '/article/:article' => Route::r(
        context: 'blog',
        controller: 'articles',
        action: 'details'
    ),
]
<?php

namespace App\Module\Api\Blog\Controller;

use Air\Core\Controller;
use App\Model\Article;

class Articles extends Controller
{
    public function details(Article $article): array
    {
        return $article->toArray();
    }
}

Имя параметра $article должно совпадать с именем route-параметра :article. По умолчанию AirCMS пытается найти модель по primary field, обычно это id.

Fallback с id на url

Если lookup-поле — id, но значение не похоже на MongoDB ObjectId, AirCMS пробует загрузить модель по полю url. Это удобно для slug-URL:

/article/64f1e8f6b2d0e2a0a1b2c3d4    # поиск по id
/article/hello-world                     # fallback-поиск по url

Модель по другому полю через PHPDoc

Чтобы явно указать поле для поиска, используется PHPDoc у action-метода. После имени параметра пишется |field.

/**
 * @param Article $article|url
 */
public function details(Article $article): array
{
    return $article->toArray();
}

Теперь $article будет загружаться по полю url, а не по id.

Модель с дополнительными условиями

В PHPDoc можно добавить JSON-условия после &. Они будут добавлены к условию поиска.

/**
 * @param Article $article|url&{"enabled":true}
 */
public function details(Article $article): array
{
    return $article->toArray();
}

Такой action загрузит статью по url и дополнительно потребует enabled = true.

Nullable model injection

Если модель может быть не найдена, лучше явно разрешить null в сигнатуре. Это особенно важно при strictInject: true, когда обычный one() может вернуть null.

/**
 * @param Article $article|url
 */
public function details(?Article $article = null): array
{
    if (!$article) {
        $this->getResponse()->setStatusCode(404);

        return [
            'error' => 'Article was not found',
        ];
    }

    return $article->toArray();
}
Практика: если action принимает модель без ?, а модель не найдена, PHP может получить несовместимый тип аргумента. Для публичных detail endpoints безопаснее использовать ?Model $model = null и вернуть 404 вручную.

Injection typed objects

Если action-параметр типизирован классом, который не является моделью, AirCMS создаёт объект через new ClassName($value). Это хорошо работает с объектами, которые наследуются от Air\Type\TypeAbstract, потому что TypeAbstract умеет принимать массив данных.

Typed object для фильтра

app/Type/PropertyFilter.php
<?php

namespace App\Type;

use Air\Type\TypeAbstract;

class PropertyFilter extends TypeAbstract
{
    public ?string $type = null;
    public ?int $minPrice = null;
    public ?int $maxPrice = null;

    /**
     * @var string[]
     */
    public array $districts = [];
}
GET /api/properties?filter[type]=apartment&filter[minPrice]=100000&filter[maxPrice]=250000&filter[districts][]=center
use App\Type\PropertyFilter;

public function index(PropertyFilter $filter): array
{
    return [
        'type' => $filter->type,
        'minPrice' => $filter->minPrice,
        'maxPrice' => $filter->maxPrice,
        'districts' => $filter->districts,
    ];
}

Здесь параметр filter приходит как вложенный массив, а AirCMS создаёт из него PropertyFilter.

Typed object из JSON body

{
    "filter": {
        "type": "house",
        "minPrice": 150000,
        "districts": ["center", "north"]
    }
}
public function search(PropertyFilter $filter): array
{
    return $filter->toArray();
}
Важно: имя параметра action должно совпадать с ключом в запросе. Для PropertyFilter $filter данные должны прийти в параметре filter.

Custom injector

Router также поддерживает кастомный injector на уровне конкретного route. Это callback, который получает значение route-параметра и возвращает готовое значение для action.

Так как Route::r() возвращает обычный массив, дополнительные настройки можно добавить через объединение массивов.

routes: [
    '/secure/:token' => Route::r(
        controller: 'secure',
        action: 'index'
    ) + [
        'injector' => [
            'token' => fn(?string $token) => hash('sha256', (string)$token),
        ],
    ],
]
public function index(string $token): array
{
    return [
        'tokenHash' => $token,
    ];
}

Custom injector стоит использовать для специальных случаев: токены, нормализация параметров, предварительная расшифровка, создание value object.

Ручное получение параметров

Injection удобен, но иногда проще явно получить параметры через controller helpers.

public function index(): array
{
    $page = (int)$this->getParam('page', 1);
    $filter = $this->getParam('filter', []);
    $allParams = $this->getParams();

    return [
        'page' => $page,
        'filter' => $filter,
        'allParams' => $allParams,
    ];
}
МетодЧто делает
$this->getParam($name, $default)Берёт параметр из request params, а затем из GET-параметров.
$this->getParams()Возвращает объединённый набор request params и GET params.
$this->getRequest()->getGet($name)Берёт значение только из GET.
$this->getRequest()->getPost($name)Берёт значение только из POST/body.
$this->getRouter()->getUrlParams()Возвращает параметры, извлечённые из URI-шаблона и статических params.

Генерация URL

Кроме описания входящих routes, Air\Core\Route умеет собирать URL по route-настройкам. Это удобно в UI, редиректах и ссылках между страницами.

use Air\Core\Route;

$url = Route::a(
    context: 'blog',
    controller: 'articles',
    action: 'details',
    params: [
        'article' => 'hello-world',
    ]
);

Если в конфигурации есть route /article/:article, результатом будет примерно:

/article/hello-world

Если подходящий route не найден, Router соберёт fallback-URI из controller/action и query string.

Большой пример

Ниже пример API для блога: список статей, детали по slug, создание статьи из JSON body и поиск с typed object.

config.php
routes: [
    '/articles' => Route::r(
        context: 'blog',
        controller: 'articles'
    ),

    '/article/:article' => Route::r(
        context: 'blog',
        controller: 'articles',
        action: 'details'
    ),

    '/article/create' => Route::r(
        context: 'blog',
        controller: 'articles',
        action: 'create'
    ),

    '/articles/search' => Route::r(
        context: 'blog',
        controller: 'articles',
        action: 'search'
    ),
]
app/Module/Api/Blog/Controller/Articles.php
<?php

namespace App\Module\Api\Blog\Controller;

use Air\Core\Controller;
use App\Model\Article;
use App\Type\ArticleFilter;

class Articles extends Controller
{
    public function index(int $page = 1, int $limit = 20): array
    {
        return [
            'page' => $page,
            'limit' => $limit,
            'items' => [],
        ];
    }

    /**
     * @param Article $article|url&{"enabled":true}
     */
    public function details(?Article $article = null): array
    {
        if (!$article) {
            $this->getResponse()->setStatusCode(404);

            return [
                'error' => 'Article was not found',
            ];
        }

        return $article->toArray();
    }

    public function create(
        string $title,
        string $description = '',
        bool $enabled = false,
        array $tags = []
    ): array {
        $article = Article::insert([
            'title' => $title,
            'description' => $description,
            'enabled' => $enabled,
            'tags' => $tags,
        ]);

        return $article->toArray();
    }

    public function search(ArticleFilter $filter): array
    {
        return [
            'filter' => $filter->toArray(),
            'items' => [],
        ];
    }
}

Практические рекомендации

  • Для публичного API включай strictRoutes: true, чтобы не было случайных endpoints.
  • Для detail endpoints используй явный action, например details(), а не перегружай index().
  • Имена route-параметров называй так же, как параметры action: :article → $article.
  • Для моделей по slug используй PHPDoc @param Article $article|url.
  • Для фильтров и сложных входных данных используй typed objects на базе TypeAbstract.
