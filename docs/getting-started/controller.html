Controllers

Controller в AirCMS — это класс, который получает управление после того, как router определил module, context, controller и action. Внутри controller обычно находится прикладная логика endpoint-а: чтение параметров, guard-проверки, работа с моделями, подготовка данных для API или передача данных во view.

Что такое Controller

Controller — это объект, который связывает HTTP/CLI-запрос с кодом приложения. В AirCMS controller обычно наследуется от Air\Core\Controller и располагается внутри активного module/context.

Например route:

'/article/:article' => Route::r(
    context: 'blog',
    controller: 'articles',
    action: 'details'
),

для API-модуля будет искать такой класс и метод:

app/Module/Api/Blog/Controller/Articles.php

App\Module\Api\Blog\Controller\Articles::details()
Важно: если action не указан, AirCMS вызывает index(). Если controller не указан, используется controller Index. Если context не указан, controller ищется напрямую в папке module: App\Module\Api\Controller\....

Когда запускается controller

Controller запускается в методе Air\Core\Front::run(). До controller-а AirCMS уже успевает создать Request, Response, Router, определить активный module и route, подготовить View и выполнить preRun() у plugins.

Упрощённый порядок выполнения:

  1. Router определяет module, context, controller и action.
  2. FrontHelper::getView() создаёт и настраивает Air\View\View.
  3. FrontHelper::getControllerClassName() определяет имя controller-класса.
  4. AirCMS создаёт controller через new ControllerClass().
  5. В controller передаются Request, Response, Router и View.
  6. Запускаются plugins preRun().
  7. Если plugins разрешили выполнение, вызывается controller->init().
  8. AirCMS вызывает action с автоматическим injection параметров.
  9. После action вызывается controller->postRun().
  10. Результат action преобразуется в response body: JSON, string, view script или layout.
  11. Запускаются plugins postRun().
  12. Front::render() отправляет status code, headers и body.

Базовый controller

Минимальный API-controller может вернуть обычный массив. AirCMS автоматически преобразует массив в JSON.

app/Module/Api/Controller/Health.php
<?php

declare(strict_types=1);

namespace App\Module\Api\Controller;

use Air\Core\Controller;

class Health extends Controller
{
    public function index(): array
    {
        return [
            'status' => 'ok',
            'time' => time(),
        ];
    }
}

Если route ведёт на /health, он может быть описан так:

'/health' => Route::r(controller: 'health'),

Жизненный цикл controller-а

В базовом Air\Core\Controller есть два метода жизненного цикла, которые можно переопределять в своих controller-ах:

МетодКогда вызываетсяДля чего использовать
init()Перед вызовом action.Общие проверки, подготовка view, установка headers, проверка авторизации.
postRun()После выполнения action, но до финального render response.Пост-обработка, дополнительные headers, логирование, общие действия после endpoint-а.
Пример lifecycle
<?php

declare(strict_types=1);

namespace App\Module\Api\Controller;

use Air\Core\Controller;

class Articles extends Controller
{
    public function init(): void
    {
        $this->getResponse()->setHeader('Content-Type', 'application/json; charset=utf-8');
    }

    public function index(): array
    {
        return [
            'items' => [],
        ];
    }

    public function postRun(): void
    {
        $this->getResponse()->setHeader('X-Powered-By', 'AirCMS');
    }
}

Основные методы Air\Core\Controller

Controller получает доступ к request, response, router и view через встроенные методы.

МетодЧто делаетПример использования
getRequest()Возвращает объект Air\Core\Request.Получить GET/POST/route параметры вручную.
getResponse()Возвращает объект Air\Core\Response.Установить status code или header.
getRouter()Возвращает текущий Air\Core\Router.Узнать module, context, controller, action.
getView()Возвращает Air\View\View.Передать переменные в view, отключить layout, изменить script.
getParam($name, $default, $filters)Читает параметр из route/POST, затем из GET.Удобно для ручного чтения одного параметра.
getParams()Возвращает объединённые route/POST и GET параметры.Передать входные данные в form или service.
redirect($uri, $code)Отправляет Location header и завершает выполнение.Редирект в UI/admin controller.
Работа с request/response/router
public function details(): array
{
    $articleId = $this->getParam('article');
    $module = $this->getRouter()->getModule();
    $action = $this->getRouter()->getAction();

    $this->getResponse()->setStatusCode(200);
    $this->getResponse()->setHeader('X-Module', $module);

    return [
        'article' => $articleId,
        'action' => $action,
    ];
}

Что может возвращать action

AirCMS обрабатывает результат action в зависимости от типа значения.

РезультатПоведениеГде полезно
arrayАвтоматически кодируется в JSON.API endpoints.
object с toArray()Сначала вызывается toArray(), затем результат кодируется в JSON.Возврат модели или DTO.
stringСтрока становится body ответа.Простой HTML/text output.
nullAirCMS пытается auto-render view script, затем layout.UI страницы на .phtml.
 
public function json(): array
{
    return [
        'ok' => true,
    ];
}

public function plain(): string
{
    return 'Hello from AirCMS';
}

public function page(): null
{
    $this->getView()->title = 'About project';

    return null;
}

Как работать с View внутри controller-а

Для UI-модуля controller может ничего не возвращать, а только подготовить данные для .phtml script-а. Если action возвращает null, AirCMS использует auto-render: ищет script по текущему controller/action и затем применяет layout.

Controller
<?php

declare(strict_types=1);

namespace App\Module\Ui\Controller;

use Air\Core\Controller;
use App\Model\Article;

class Articles extends Controller
{
    public function details(Article $article): null
    {
        $this->getView()->article = $article;
        $this->getView()->title = $article->title;

        return null;
    }
}
View script: app/Module/Ui/View/Scripts/articles/details.phtml
<article>
    <h1><?php echo $this->article->title; ?></h1>
    <div><?php echo $this->article->description; ?></div>
</article>
Layout: app/Module/Ui/View/Layouts/index.phtml
<!doctype html>
<html lang="ru">
<head>
    <?php echo $this->head(); ?>
    <title><?php echo $this->title; ?></title>
</head>
<body>
    <main>
        <?php echo $this->getContent(); ?>
    </main>
</body>
</html>

Ручное управление View

Иногда нужно отключить layout, отключить auto-render, выбрать другой script или вернуть HTML вручную.

Отключить layout
public function fragment(): null
{
    $this->getView()->setLayoutEnabled(false);
    $this->getView()->message = 'Fragment content';

    return null;
}
Выбрать другой script
public function preview(): null
{
    $this->getView()->setScript('articles/card');
    $this->getView()->setLayoutEnabled(false);

    return null;
}
Вернуть HTML вручную
public function raw(): string
{
    $this->getView()->setLayoutEnabled(false);

    return '<strong>Raw HTML</strong>';
}

Как работать с Guards

Air\Guard\Guard — это небольшой assertion-helper. Его удобно использовать в controller-ах для проверки доступа, обязательных условий, статуса пользователя, наличия модели или корректности состояния.

Если условие не проходит, Guard::ensure() выбрасывает исключение. Это исключение затем попадает в стандартный error handling AirCMS.

Guard внутри action
<?php

use Air\Guard\Guard;
use Air\Exception\NotAllowed;

public function delete(Article $article): array
{
    Guard::ensure(
        condition: $this->isAdmin(),
        fail: new NotAllowed('Only administrator can delete articles')
    );

    $article->remove();

    return [
        'success' => true,
    ];
}
Несколько условий
use Air\Guard\Guard;
use RuntimeException;

public function publish(Article $article): array
{
    Guard::ensure([
        fn() => $article->id !== null,
        fn() => $article->enabled === true,
        fn() => strlen($article->title) > 0,
    ], function (int $failedAt) {
        throw new RuntimeException('Guard failed at condition #' . $failedAt);
    });

    $article->publishedAt = time();
    $article->save();

    return $article->toArray();
}
Guard в init()
<?php

namespace App\Module\Api\Controller;

use Air\Core\Controller;
use Air\Guard\Guard;
use Air\Exception\NotAllowed;

abstract class ProtectedController extends Controller
{
    public function init(): void
    {
        Guard::ensure(
            condition: $this->getRequest()->getHeader('Authorization') !== null,
            fail: new NotAllowed('Authorization header is required')
        );
    }
}

Базовый controller проекта

Если в проекте много API endpoints, удобно сделать свой базовый controller и наследовать остальные controller-ы от него. Так можно централизовать CORS headers, авторизацию, чтение пользователя, guard-проверки и формат ответов.

app/Module/Api/Controller/AppController.php
<?php

declare(strict_types=1);

namespace App\Module\Api\Controller;

use Air\Core\Controller;
use Air\Exception\NotAllowed;
use Air\Guard\Guard;

abstract class AppController extends Controller
{
    protected ?string $token = null;

    public function init(): void
    {
        $this->getResponse()->setHeader('Content-Type', 'application/json; charset=utf-8');

        $this->token = $this->getRequest()->getHeader('Authorization');
    }

    protected function requireAuth(): void
    {
        Guard::ensure(
            condition: !empty($this->token),
            fail: new NotAllowed('Authentication is required')
        );
    }

    protected function success(array $data = []): array
    {
        return [
            'success' => true,
            'data' => $data,
        ];
    }
}
Наследование
<?php

declare(strict_types=1);

namespace App\Module\Api\Controller;

class Profile extends AppController
{
    public function index(): array
    {
        $this->requireAuth();

        return $this->success([
            'profile' => [],
        ]);
    }
}

Controller и action injection

Action может принимать параметры напрямую. AirCMS передаёт в action route-параметры, GET/POST/JSON параметры, модели и typed objects. Подробнее это описано в разделе Routing, но для controller-а важно понимать сам принцип: параметры action являются частью публичного контракта endpoint-а.

use App\Model\Article;
use App\Type\ArticleFilter;

class Articles extends Controller
{
    /**
     * @param Article $article|url
     */
    public function details(Article $article): array
    {
        return $article->toArray();
    }

    public function search(ArticleFilter $filter, int $page = 1): array
    {
        return [
            'filter' => $filter->toArray(),
            'page' => $page,
            'items' => [],
        ];
    }
}

Status code, headers и redirects

Controller может напрямую управлять response object. Это полезно для 404, 403, custom headers, file responses, redirects и API status codes.

public function details(?Article $article = null): array
{
    if (!$article) {
        $this->getResponse()->setStatusCode(404);

        return [
            'error' => 'Article was not found',
        ];
    }

    $this->getResponse()->setHeader('X-Article-ID', $article->id);

    return $article->toArray();
}

public function oldPage(): void
{
    $this->redirect('/new-page', 301);
}

Большой практический пример

Ниже пример controller-а, который показывает несколько типичных приёмов сразу: init(), headers, guard, model injection, optional scalar-параметры, status code и единый формат ответа.

app/Module/Api/Blog/Controller/Articles.php
<?php

declare(strict_types=1);

namespace App\Module\Api\Blog\Controller;

use Air\Core\Controller;
use Air\Exception\NotAllowed;
use Air\Guard\Guard;
use App\Model\Article;

class Articles extends Controller
{
    public function init(): void
    {
        $this->getResponse()->setHeader('Content-Type', 'application/json; charset=utf-8');
    }

    public function index(int $page = 1, int $limit = 20): array
    {
        return [
            'page' => $page,
            'limit' => $limit,
            'items' => Article::all(
                search: ['enabled' => true],
                sort: ['createdAt' => -1],
                count: $limit,
                offset: ($page - 1) * $limit
            ),
        ];
    }

    /**
     * @param Article $article|url
     */
    public function details(?Article $article = null): array
    {
        if (!$article) {
            $this->getResponse()->setStatusCode(404);

            return [
                'error' => 'Article was not found',
            ];
        }

        return $article->toArray();
    }

    public function remove(Article $article): array
    {
        Guard::ensure(
            condition: $this->getRequest()->getHeader('Authorization') !== null,
            fail: new NotAllowed('Authorization is required')
        );

        $article->remove();

        return [
            'success' => true,
        ];
    }

    public function postRun(): void
    {
        $this->getResponse()->setHeader('X-Framework', 'AirCMS');
    }
}

Рекомендации

  • Не перегружай controller слишком большим количеством бизнес-логики; сложную логику лучше выносить в service-классы.
  • Используй init() для общих проверок и headers, но не делай в нём тяжёлые операции без необходимости.
  • Для API возвращай массивы или объекты с toArray().
  • Для UI-страниц возвращай null и используй auto-render view script-а.
  • Для авторизации и обязательных условий используй Guard::ensure().
  • Для повторяющихся API-паттернов создай project-level base controller.
  • Не используй action names, совпадающие с методами базового Air\Core\Controller, например init, postRun, getView.
