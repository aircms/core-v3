Plugins

Plugins в AirCMS — это слой перехвата запроса до и после выполнения controller action. Через них удобно добавлять CORS, авторизацию, API-key проверку, логирование, rate limit, security headers, maintenance mode и другую сквозную логику.

Что такое plugin

Plugin — это PHP-класс, который наследуется от Air\Core\Plugin и может реализовать два hook-метода: preRun() и postRun(). AirCMS автоматически находит plugin-классы в специальных папках активного приложения, создаёт их экземпляры и вызывает их во время обработки запроса.

Главная идея: controller должен заниматься бизнес-логикой конкретного endpoint-а, а plugin — общей логикой, которая повторяется во многих endpoint-ах: headers, auth, CORS, audit log, блокировки, ограничения доступа.
Базовый класс Air\Core\Plugin
<?php

namespace Air\Core;

class Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        return true;
    }

    public function postRun(Request $request, Response $response, Router $router): bool
    {
        return true;
    }
}

Оба метода получают один и тот же набор объектов: Request, Response и Router. Через них plugin может прочитать входящий запрос, узнать текущий module/context/controller/action, добавить headers, изменить status code или полностью остановить выполнение action.

Когда запускаются plugins

Plugins запускаются внутри Front::run(), когда AirCMS уже определил route, view и controller class, но ещё не вызвал controller->init() и сам action.

  1. AirCMS определяет активный module по domain/CLI route.
  2. Router находит route и заполняет context, controller, action и URL-параметры.
  3. AirCMS определяет controller class и создаёт controller object.
  4. AirCMS загружает подходящие plugins.
  5. Для каждого plugin вызывается preRun().
  6. Если все preRun() вернули true, запускаются controller->init(), action и controller->postRun().
  7. Формируется response body: JSON, string, view script или layout.
  8. Для каждого plugin вызывается postRun().
  9. AirCMS отправляет status code, headers и body клиенту.
Важно: если любой preRun() вернёт false, controller action не будет выполнен. В этом случае postRun() также не вызывается, потому что основной блок выполнения action пропускается.

Аргументы plugin-методов

Методы preRun() и postRun() принимают три объекта.

Аргумент Что содержит Где полезен
Request $request HTTP method, URI, domain, IP, user-agent, headers, GET/POST/JSON params, files. Auth, CORS, rate limit, логирование запроса, проверка token/api-key.
Response $response Status code, status message, response headers, response body. Добавить headers, вернуть ошибку, остановить request, изменить body после action.
Router $router Module, context, controller, action, URL params, route config, URL assembler. Применять plugin только к конкретному context/controller/action.
Доступ к Request и Router
<?php

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;

class Debug extends Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        $method = $request->getMethod();
        $uri = $request->getUri();
        $ip = $request->getIp();

        $module = $router->getModule();
        $context = $router->getContext();
        $controller = $router->getController();
        $action = $router->getAction();

        return true;
    }
}

На что влияет возвращаемое значение

preRun(): true

Запрос продолжает выполняться. AirCMS переходит к следующему plugin, затем запускает controller action.

preRun(): false

AirCMS останавливает выполнение запроса до controller action. Такой plugin должен сам подготовить response: status code, headers и body.

Остановка запроса из preRun()
<?php

namespace App\Module\Api\Plugin;

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;

class ApiKey extends Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        $apiKey = $request->getHeader('x-api-key');

        if ($apiKey !== getenv('APP_API_KEY')) {
            $response->setStatusCode(401);
            $response->setHeader('Content-Type', 'application/json; charset=utf-8');
            $response->setBody(json_encode([
                'success' => false,
                'error' => 'Invalid API key',
            ]));

            return false;
        }

        return true;
    }
}

postRun(): true

AirCMS продолжает выполнять следующие postRun() plugins.

postRun(): false

Останавливает выполнение следующих postRun() plugins, но не отменяет action: к этому моменту action уже выполнен и response body уже сформирован.

Модификация response после action
<?php

namespace App\Module\Api\Plugin;

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;

class JsonHeaders extends Plugin
{
    public function postRun(Request $request, Response $response, Router $router): bool
    {
        $response->setHeader('Content-Type', 'application/json; charset=utf-8');
        $response->setHeader('X-Powered-By', 'AirCMS');

        return true;
    }
}

Где AirCMS ищет plugins

AirCMS ищет plugins на трёх уровнях. Это позволяет подключать общую логику ко всему приложению, к конкретному module или только к конкретному context.

Путь Namespace Когда запускается
app/Module/Plugin/*.php App\Module\Plugin Для всех modules: admin, api, ui, cli.
app/Module/Api/Plugin/*.php App\Module\Api\Plugin Для всех routes внутри module api.
app/Module/Api/Catalog/Plugin/*.php App\Module\Api\Catalog\Plugin Только для routes с context: 'catalog' внутри module api.

Порядок загрузки уровней: сначала global plugins, затем module plugins, затем context plugins. Внутри одной папки файлы загружаются через glob(), поэтому для понятного порядка лучше использовать имена с числовым префиксом.

Пример структуры plugins
app/
    Module/
        Plugin/
            010Maintenance.php
            020SecurityHeaders.php
        Api/
            Plugin/
                010Cors.php
                020ApiAuth.php
            Catalog/
                Plugin/
                    010CatalogLocale.php

Plugin без context: global-level

Global plugin лежит в app/Module/Plugin. Он запускается для любого module, если request дошёл до выполнения AirCMS. Такой уровень подходит для security headers, maintenance mode, общего audit log, проверки IP или общих cookies.

app/Module/Plugin/SecurityHeaders.php
<?php

namespace App\Module\Plugin;

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;

class SecurityHeaders extends Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        $response->setHeader('X-Frame-Options', 'SAMEORIGIN');
        $response->setHeader('X-Content-Type-Options', 'nosniff');
        $response->setHeader('Referrer-Policy', 'strict-origin-when-cross-origin');

        return true;
    }
}

Plugin для module

Module-level plugin лежит внутри конкретного module, например app/Module/Api/Plugin. Он запускается для всех API routes, независимо от context. Это удобно для CORS, JSON headers, API auth, API logging.

app/Module/Api/Plugin/Cors.php
<?php

namespace App\Module\Api\Plugin;

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;

class Cors extends Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        $response->setHeader('Access-Control-Allow-Origin', '*');
        $response->setHeader('Access-Control-Allow-Headers', 'Content-Type, Authorization, X-Api-Key');
        $response->setHeader('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE, OPTIONS');

        if ($request->getMethod() === Request::METHOD_OPTIONS) {
            $response->setStatusCode(204);
            $response->setBody('');

            return false;
        }

        return true;
    }
}

Plugin для context

Context-level plugin лежит внутри папки context. Он запускается только для routes, где указан соответствующий context. Например, если route использует context: 'catalog', AirCMS дополнительно проверит plugins в app/Module/Api/Catalog/Plugin.

Route с context: catalog
<?php

use Air\Config;
use Air\Core\Route;

return Config::defaults(
    project: 'APP',

    api: fn() => Config::api(
        domain: 'api.*',
        routes: [
            '/catalog/property/:property' => Route::r(
                context: 'catalog',
                controller: 'property',
                action: 'details'
            ),
        ]
    )
);
app/Module/Api/Catalog/Plugin/CatalogAccess.php
<?php

namespace App\Module\Api\Catalog\Plugin;

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;

class CatalogAccess extends Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        if ($router->getContext() !== 'catalog') {
            return true;
        }

        $country = $request->getParam('country');

        if ($country === 'blocked-country') {
            $response->setStatusCode(403);
            $response->setBody(json_encode([
                'success' => false,
                'error' => 'Catalog is not available for this country',
            ]));

            return false;
        }

        return true;
    }
}

Plugin, который реагирует на controller/action

Через Router plugin может понять, какой именно endpoint сейчас выполняется. Это полезно, если один plugin должен работать не для всего module, а только для нескольких controller/action.

Проверка controller/action
<?php

namespace App\Module\Api\Plugin;

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;

class Auth extends Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        $publicActions = [
            'auth.login',
            'auth.refresh',
            'health.index',
        ];

        $currentAction = $router->getController() . '.' . $router->getAction();

        if (in_array($currentAction, $publicActions, true)) {
            return true;
        }

        $token = $request->getHeader('authorization');

        if (!$token) {
            $response->setStatusCode(401);
            $response->setBody(json_encode([
                'success' => false,
                'error' => 'Authorization header is required',
            ]));

            return false;
        }

        return true;
    }
}

Логирование запросов и ответов

Plugins хорошо подходят для логирования, потому что preRun() видит входящий request, а postRun() видит уже сформированный response.

Логирование через Air\Log
<?php

namespace App\Module\Api\Plugin;

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;
use Air\Log;

class ApiLog extends Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        Log::info('API request', [
            'method' => $request->getMethod(),
            'uri' => $request->getUri(),
            'ip' => $request->getIp(),
            'controller' => $router->getController(),
            'action' => $router->getAction(),
            'params' => $request->getParams(),
        ]);

        return true;
    }

    public function postRun(Request $request, Response $response, Router $router): bool
    {
        Log::info('API response', [
            'uri' => $request->getUri(),
            'statusCode' => $response->getStatusCode(),
            'controller' => $router->getController(),
            'action' => $router->getAction(),
        ]);

        return true;
    }
}
Важно: Air\Log пишет записи только если в конфигурации включены logs. Обычно это настройка вида air.logs.enabled. Если logs выключены, вызовы Log::info() и Log::error() не сохранят запись.

Maintenance mode

Global plugin можно использовать для временного отключения публичной части сайта или API. В таком plugin удобно разрешить доступ только для CLI, admin или определённых IP.

Maintenance plugin
<?php

namespace App\Module\Plugin;

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;

class Maintenance extends Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        $enabled = getenv('APP_MAINTENANCE') === '1';

        if (!$enabled) {
            return true;
        }

        if ($router->getModule() === 'admin') {
            return true;
        }

        if (in_array($request->getIp(), ['127.0.0.1', '::1'], true)) {
            return true;
        }

        $response->setStatusCode(503);
        $response->setHeader('Retry-After', '3600');
        $response->setBody('Service temporarily unavailable');

        return false;
    }
}

Определение языка через plugin

Context-level или module-level plugin можно использовать для чтения языка из URL, header или query string. Например, API может принимать ?lang=en, а plugin — сохранять выбранный язык в request params, чтобы action получил его через injection.

Передача lang дальше в action
<?php

namespace App\Module\Api\Plugin;

use Air\Core\Plugin;
use Air\Core\Request;
use Air\Core\Response;
use Air\Core\Router;

class Locale extends Plugin
{
    public function preRun(Request $request, Response $response, Router $router): bool
    {
        $lang = $request->getParam('lang', 'ru');

        if (!in_array($lang, ['ru', 'en', 'es', 'zh'], true)) {
            $lang = 'ru';
        }

        $request->setGetParam('lang', $lang);

        return true;
    }
}
Action получает lang через injection
<?php

namespace App\Module\Api\Controller;

use Air\Core\Controller;

class Articles extends Controller
{
    public function index(string $lang = 'ru'): array
    {
        return [
            'language' => $lang,
            'items' => [],
        ];
    }
}

Для чего plugins полезны

CORS

Добавить Access-Control-Allow-* headers и быстро отвечать на OPTIONS requests.

Auth / API keys

Проверить JWT, session, API key или подпись до запуска controller action.

Logging

Сохранять входящий request, выбранный route, status code и ошибки интеграций.

Rate limit

Ограничивать частоту запросов по IP, user id, token или endpoint-у.

Security headers

Добавлять X-Frame-Options, Content-Security-Policy, Referrer-Policy.

Maintenance mode

Отключать публичные modules, оставляя доступ для admin, CLI или выбранных IP.

Практические рекомендации

  • Не помещайте бизнес-логику конкретного endpoint-а в plugin. Для этого лучше использовать controller/service.
  • Используйте global plugins только для действительно общей логики.
  • Для API-специфичной логики используйте app/Module/Api/Plugin.
  • Для context-специфичной логики используйте app/Module/Api/{Context}/Plugin.
  • Если preRun() возвращает false, всегда явно задавайте status code и body.
  • Не выбрасывайте исключения в plugin без необходимости: это отправит запрос в error handling pipeline.
  • Если порядок plugins важен, используйте имена вроде 010Cors.php, 020Auth.php, 030Log.php.
