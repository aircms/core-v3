Worker

Worker в AirCMS — это специальный CLI-контроллер для фоновых задач: обработки очередей, отправки уведомлений, импорта, парсинга, синхронизации и периодической обработки данных.

Что такое Worker

Worker — это controller, который запускается не через браузер, а из командной строки через тот же входной файл www/index.php. Он использует общий механизм AirCMS: конфигурацию, роутер, request, controller, dependency/injection-логику и обработку ошибок.

Главное отличие от обычного controller в том, что Air\Core\Worker предназначен для повторного выполнения одного метода в цикле. Метод вызывается снова и снова, пока не вернёт строгое значение false.

Важно: методы задач в Worker обычно нужно делать protected. Если сделать task-method публичным, он может быть вызван как обычный action один раз, без worker-цикла didStarted(), didTick(), didFinished().

Когда Worker запускается

Worker запускается, когда приложение выполняется в CLI-режиме и в командной строке передан параметр route. Внутри Request::fillRequestFromCli() AirCMS читает аргументы командной строки, берёт значение route, превращает его в URI и устанавливает домен cli. После этого обычный роутер AirCMS выбирает CLI-модуль и controller/action.

Примеры запуска
php www/index.php route=notification/email
      php www/index.php route=notification/telegram
      php www/index.php route=catalog/reindex limit=100 offset=0 dryRun=1

В примере route=notification/email будет преобразован в URI /notification/email. Если CLI-модуль не работает в strict-routes режиме, такой URI будет разобран как controller notification и action email.

Конфигурация CLI-модуля

CLI-модуль подключается в основном config.php через Config::cli(). Можно использовать свободный режим, где route разбирается по URI, или strict mode, где разрешены только явно объявленные маршруты.

config.php
<?php

      use Air\Config;
      use Air\Core\Route;

      return Config::defaults(
          project: 'AIR',

          cli: fn() => Config::cli(
              strictRoutes: true,
              routes: [
                  '/notification/email' => Route::r(
                      controller: 'notification',
                      action: 'email'
                  ),
                  '/notification/telegram' => Route::r(
                      controller: 'notification',
                      action: 'telegram'
                  ),
                  '/catalog/reindex' => Route::r(
                      controller: 'catalog',
                      action: 'reindex'
                  ),
              ],
          ),
      );
Параметр Что делает
strictRoutes Если true, AirCMS разрешает только явно описанные CLI routes. Если route не найден, будет выброшено исключение роутинга.
strictInject Влияет на model injection. При true используется обычный one(), при false — fetchOne().
routes Список CLI-маршрутов. Ключ — URI, значение — Route::r().
require Дополнительные PHP-файлы, которые нужно подключить при bootstrap CLI-модуля.

Где находится Worker

Worker-классы находятся в CLI-модуле проекта. Для route notification/email AirCMS будет искать controller примерно по такому пути:

Структура файла
app/
      └── Module/
          └── Cli/
              └── Controller/
                  └── Notification.php

И соответствующий class name:

App\Module\Cli\Controller\Notification

Базовый пример Worker

Ниже пример worker-а, который обрабатывает очереди Email и Telegram. Методы email() и telegram() объявлены как protected, чтобы вызов прошёл через Worker::__call() и запустился worker-цикл.

app/Module/Cli/Controller/Notification.php
<?php

      declare(strict_types=1);

      namespace App\Module\Cli\Controller;

      use Air\Core\Worker;
      use Air\Email;
      use Air\Telegram;

      class Notification extends Worker
      {
          protected function email(): ?bool
          {
              return Email::consume();
          }

          protected function telegram(): ?bool
          {
              return Telegram::consume();
          }
      }

Запуск:

php www/index.php route=notification/email
      php www/index.php route=notification/telegram

Жизненный цикл Worker

Worker использует общий жизненный цикл controller-а и добавляет свои хуки вокруг цикла выполнения задачи.

  1. Запускается www/index.php.
  2. Front загружает config и bootstrap.
  3. Request::fillRequestFromCli() читает CLI arguments.
  4. Router определяет CLI module, controller и action.
  5. Создаётся worker controller.
  6. Выполняются plugins preRun(), если они есть.
  7. Вызывается Controller::init().
  8. Вызов protected action попадает в Worker::__call().
  9. Один раз вызывается didStarted().
  10. Целевой метод выполняется в цикле.
  11. После каждой успешной итерации вызывается didTick() и затем sleep().
  12. Когда целевой метод вернул false, цикл завершается.
  13. Один раз вызывается didFinished().
  14. После завершения worker-цикла вызывается Controller::postRun().
  15. Выполняются plugins postRun(), если они есть.
didTick не вызывается для последней итерации, которая вернула false. В коде Worker сначала проверяет результат на false, и только потом вызывает didTick().

Методы жизненного цикла

Worker наследует методы обычного controller-а и добавляет три собственных hook-метода.

Метод Когда вызывается Для чего использовать
init() Один раз перед запуском action/worker method. Проверить окружение, подготовить сервисы, установить лимиты, прочитать общие параметры.
didStarted(string $method, array $params) Один раз перед началом worker-цикла. Записать старт в лог, вывести информацию в консоль, сохранить время начала.
didTick(string $method, array $params) После каждой итерации, если результат не равен false. Логировать heartbeat, освобождать ресурсы, выводить прогресс.
didFinished(string $method, array $params) Один раз после выхода из цикла. Записать завершение в лог, отправить уведомление, закрыть соединения.
postRun() После завершения worker-цикла. Финальная очистка на уровне controller-а.
Worker с lifecycle hooks
<?php

      declare(strict_types=1);

      namespace App\Module\Cli\Controller;

      use Air\Core\Worker;
      use Air\Log;

      class Import extends Worker
      {
          public function init(): void
          {
              ini_set('memory_limit', '512M');
              set_time_limit(0);
          }

          protected function didStarted(string $method, array $params = []): void
          {
              Log::info('Worker started', [
                  'method' => $method,
                  'params' => $params,
              ]);
          }

          protected function didTick(string $method, array $params = []): void
          {
              Log::info('Worker tick', [
                  'method' => $method,
              ]);
          }

          protected function didFinished(string $method, array $params = []): void
          {
              Log::info('Worker finished', [
                  'method' => $method,
              ]);
          }

          public function postRun(): void
          {
              gc_collect_cycles();
          }

          protected function products(): ?bool
          {
              // Возвращайте false, когда больше нечего обрабатывать.
              return false;
          }
      }

На что влияет возвращаемое значение

Возвращаемое значение целевого worker-метода управляет циклом. AirCMS проверяет результат строго через $r === false.

Возвращаемое значение Что произойдёт
false Worker остановит цикл, вызовет didFinished(), затем postRun().
true Worker вызовет didTick(), подождёт air.worker.sleep секунд и запустит следующую итерацию.
null Цикл продолжится, потому что null !== false. Это может случайно создать бесконечный worker.
Любое другое значение Цикл тоже продолжится, потому что останавливает только строгое false.
Явное управление циклом
protected function email(): ?bool
      {
          $processed = Email::consume();

          if (!$processed) {
              return false;
          }

          return true;
      }
Если worker должен выполнить задачу один раз и завершиться, верните false после выполнения работы. Если нужен бесконечный daemon-процесс, возвращайте true, пока процесс должен продолжаться.

Пауза между итерациями

После каждой успешной итерации Worker вызывает sleep(). Значение берётся из конфигурации air.worker.sleep. Если значение не задано, используется 1 секунда.

Базовая CLI-конфигурация
<?php

      return Config::defaults(
          project: 'AIR',

          cli: fn() => Config::cli(
              routes: [
                  '/notification/email' => Route::r(
                      controller: 'notification',
                      action: 'email'
                  ),
              ],
          ),
      );

Если нужно изменить sleep, это можно сделать через общий config project-а, если в проекте используется собственное расширение секции air, или через bootstrap/override конфигурации. Внутри Worker используется такой путь:

Front::getInstance()->getConfig()['air']['worker']['sleep'] ?? 1

Параметры командной строки

AirCMS читает CLI-параметры в формате key=value. Параметр route используется для выбора controller/action, остальные параметры попадают в request params.

Запуск с параметрами
php www/index.php route=catalog/reindex limit=100 offset=0 dryRun=1 language=ru

Внутри request будут доступны:

limit=100
      offset=0
      dryRun=1
      language=ru
CLI-параметры приходят как строки. Если нужно число или boolean — приводите тип вручную внутри worker-а.

Как читать CLI-параметры

Есть два практических способа: читать параметры через $this->getParam() или принимать их как аргументы worker-метода. Для Worker безопаснее принимать параметры через ...$params, особенно если набор параметров может меняться.

Чтение через getParam()
protected function reindex(...$params): ?bool
      {
          $limit = (int)$this->getParam('limit', 100);
          $offset = (int)$this->getParam('offset', 0);
          $dryRun = (bool)$this->getParam('dryRun', false);
          $language = (string)$this->getParam('language', 'ru');

          // Здесь можно обработать часть данных.

          return false;
      }
Чтение через variadic params
protected function reindex(...$params): ?bool
      {
          $limit = (int)($params['limit'] ?? 100);
          $offset = (int)($params['offset'] ?? 0);
          $dryRun = (bool)($params['dryRun'] ?? false);
          $language = (string)($params['language'] ?? 'ru');

          return false;
      }
Явные аргументы метода
protected function reindex(
          string $limit = '100',
          string $offset = '0',
          string $dryRun = '0',
          string $language = 'ru'
      ): ?bool {
          $limit = (int)$limit;
          $offset = (int)$offset;
          $dryRun = (bool)$dryRun;

          return false;
      }
В текущем механизме Worker параметры командной строки передаются в worker-метод как raw params. Поэтому для CLI лучше считать их строками и приводить типы вручную.

Пример worker-а с пакетной обработкой

Частый сценарий — обработать данные порциями. Например, импортировать или переиндексировать записи пачками.

app/Module/Cli/Controller/Catalog.php
<?php

      declare(strict_types=1);

      namespace App\Module\Cli\Controller;

      use Air\Core\Worker;
      use Air\Log;
      use App\Model\Product;

      class Catalog extends Worker
      {
          private int $offset = 0;
          private int $processed = 0;

          protected function reindex(...$params): ?bool
          {
              $limit = (int)($params['limit'] ?? 100);
              $language = (string)($params['language'] ?? 'ru');

              $products = Product::fetchAll(
                  [
                      'language' => $language,
                  ],
                  [
                      'createdAt' => 1,
                  ],
                  count: $limit,
                  offset: $this->offset
              );

              if (!count($products)) {
                  Log::info('Catalog reindex finished', [
                      'processed' => $this->processed,
                      'language' => $language,
                  ]);

                  return false;
              }

              foreach ($products as $product) {
                  // Выполнить переиндексацию записи.
                  $this->processed++;
              }

              $this->offset += $limit;

              return true;
          }
      }
Запуск
php www/index.php route=catalog/reindex limit=200 language=ru

Одноразовая CLI-команда

Если команда должна выполниться один раз, можно всё равно использовать Worker, но метод должен вернуть false после выполнения работы. Однако если цикл вообще не нужен, проще использовать обычный Controller в CLI-модуле.

<?php

      declare(strict_types=1);

      namespace App\Module\Cli\Controller;

      use Air\Core\Worker;
      use Air\Log;

      class Maintenance extends Worker
      {
          protected function clearTemp(...$params): ?bool
          {
              $days = (int)($params['days'] ?? 7);

              // Очистка временных данных.

              Log::info('Temporary data was cleared', [
                  'days' => $days,
              ]);

              return false;
          }
      }
php www/index.php route=maintenance/clearTemp days=30

Supervisor

Worker обычно запускается под контролем Supervisor или systemd. Это позволяет автоматически перезапускать процесс после падения или после завершения.

Supervisor config
[program:aircms-notification-email]
      user=www-data
      command=php www/index.php route=notification/email
      directory=/var/www/project
      autostart=true
      autorestart=true
      stdout_logfile=/var/log/supervisor/aircms-email.log
      stderr_logfile=/var/log/supervisor/aircms-email-error.log

Если worker должен завершаться, когда очередь пуста, оставьте autorestart=true, и Supervisor снова поднимет процесс. Если worker должен жить постоянно, возвращайте true после успешной итерации и false только при необходимости остановки.

Практические рекомендации

  • Делайте task-methods в Worker как protected, чтобы использовался worker-цикл.
  • Возвращайте false, когда больше нечего обрабатывать.
  • Не возвращайте случайно null, если worker должен остановиться.
  • Для параметров командной строки используйте формат key=value.
  • Считайте CLI-параметры строками и приводите типы вручную.
  • Для произвольного набора параметров используйте ...$params.
  • Логируйте старт, прогресс и завершение через Air\Log.
  • Для production-запуска используйте Supervisor или systemd.
